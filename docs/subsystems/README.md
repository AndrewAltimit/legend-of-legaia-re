# Subsystems

How the runtime engine works, one page per subsystem. The retail side of each page is Ghidra-traced; the port side names the crate that implements it.

| Doc | Covers |
|---|---|
| [`engine.md`](engine.md) | The port as it is: what works, crate layering, the hosts on one engine, the fidelity-vs-enhancement model with current defaults, the legal boundary. |
| [`boot.md`](boot.md) | Boot sequence; PROT TOC into `0x801C70F0`. |
| [`asset-loader.md`](asset-loader.md) | LBA resolver + sub-asset chain. |
| [`renderer.md`](renderer.md) | TMD renderer at `FUN_8002735c` (60 GTE ops). No culling of the port's own: what drops geometry is retail's (visible-tile crop at retail framing, actor cull, per-prim rejects); the clip volume holds the whole scene (`SCENE_FAR`). |
| [`renderer-port.md`](renderer-port.md) | The port's wgpu renderer pass by pass: PSX-mode rasterisation, the enhancement passes, the screen-space overlay, VRAM capture, the battle HUD and menu pipelines, the frame profiler. |
| [`browser-host.md`](browser-host.md) | The browser host module by module: what the wasm bundles (`web-play` + `web-minigames` in both, `web-patcher` + `web-expansion` + `web-viewer` in the tool one) export for the play page, the minigames page, the game-modes page, the viewer pages, the ROM patcher and the expansion workbench. |
| [`shading.md`](shading.md) | How a pixel gets its colour: texel index -> CLUT read from **VRAM** (not the file) -> `texel * colour / 128` -> depth cue -> blend -> dither. No light source. Why exported palettes look wrong. |
| [`vr-mode.md`](vr-mode.md) | WebXR `immersive-vr` on the site's 3D pages: the flat renderer stays the geometry source, only the framebuffer and view-projection fork per eye. |
| [`audio.md`](audio.md) | PsyQ libsnd / libspu stack, SsAPI sequencer, SPU DMA engine; the cold scene-entry sequence every host owes, and how BGM parity is measured against a save state (`audio-sweep`, `pcm-retail`, `seq-differential`, `cue-differential`). |
| [`script-vm.md`](script-vm.md) | Field/event VM at `FUN_801DE840` (overlay-resident, 43 opcodes). Op `0x46` is `VIEW_WINDOW` (camera tile window, not fog); talking to an NPC is a button press, not an opcode. |
| [`script-vm-menuctrl.md`](script-vm-menuctrl.md) | Op `0x4C` `MENU_CTRL`, whose outer high nibble selects 16 sub-dispatchers; split out of `script-vm.md` for length. |
| [`tile-board.md`](tile-board.md) | Tile-board grid mode (puzzle / board minigame), NOT general town locomotion. `width×height` byte cell array (cell `2` = wall) + per-cell tile-actor rendering; installed inline in the field-VM script by op `0x49` (`_DAT_8007b450`); walk SM at `overlay_0897_801ef2b0`. |
| [`field-locomotion.md`](field-locomotion.md) | Player free-movement controller `FUN_801d01b0` (field overlay): camera-remapped held pad → direction + facing, per-frame speed, 2-unit stepping with per-axis collision `FUN_801cfe4c` against the per-scene walkability grid at `*(_DAT_1f8003ec)+0x4000` (4 sub-cell wall bits per 128-unit tile). Pinned by runtime write-watchpoint on `player+0x14/0x18`. |
| [`field-ambient-fx.md`](field-ambient-fx.md) | Field ambient animation: the bundle type-6 CLUT-walk table (12 carriers, not kingdom-only), the scene-entry ambient move-VM effect tree (MAN P1 effect scripts → `FUN_800252EC` → `FUN_80021B04`), and the mode-3 CLUT-cell HSV cycler `FUN_80019D50` behind jou's pulsating flesh + lightning. Engine `engine-core::world::ambient` + `engine-field::clut_cell_fx`. |
| [`minigame-fishing.md`](minigame-fishing.md) | Fishing: state machine (`FUN_801cf3bc`), lure and bite tick, tension-gauge reel (`FUN_801d4004`), catch scoring, point exchange and per-venue spawn tables. All three hosts run one `PondSession`. |
| [`minigame-slot-machine.md`](minigame-slot-machine.md) | Casino slot machine: reel SM (`FUN_801cf0d8`), dual RNG, **five**-payline payout (`FUN_801d13e8`). A **3D scene** through the GTE, not 2D sprites. Parser `legaia_minigame_formats::minigame_slot_scene`. |
| [`minigame-baka-fighter.md`](minigame-baka-fighter.md) | Baka Fighter duel minigame: round SM (`FUN_801d3468`), rock-paper-scissors exchange resolver (`FUN_801d3a14`), stat/combo damage, pad-vs-AI move pick; reuses the PROT 1204 battle-form party meshes. |
| [`minigame-dance.md`](minigame-dance.md) | Noa dance rhythm minigame: beat-clock state machine (`FUN_801cf470`), timing-window judge (`FUN_801d1960`, accuracy-weighted), step chart at `0x801d509c`, groove gauge `DAT_801d544c` as difficulty/multiplier. |
| [`expansion-modes.md`](expansion-modes.md) | The port's own game modes (Hold'em, the trading-card game, mini-golf, racing, prop hunt): the lockstep-ready session contract, each mode's rules, the card economy and the `SceneMode::Expansion` seat both hosts run them in. `engine-modes`, configured by a pack's `modes.toml` / `cards.toml`. |
| [`minigame-muscle-dome.md`](minigame-muscle-dome.md) | Muscle Dome arena ladder: rounds run on the general battle round SM (`FUN_801d0748`), the contest hub (`FUN_801cf870`) in PROT 0977. Not a card battle. |
| [`actor-vm.md`](actor-vm.md) | Actor / sprite VM at `FUN_801D6628` (13 opcodes) - the menu overlay's window-widget script interpreter; programs in [`window-script.md`](../formats/window-script.md). |
| [`effect-vm.md`](effect-vm.md) | Effect-bundle pool; spawn API; the three render-mode-4 emitters, all three carrying shipped content (the move VM selects them). |
| [`move-vm.md`](move-vm.md) | Move-table opcode VM at `FUN_80023070` (71 ops, JT `0x80010778`); op `0x2F` escapes to overlay extension. |
| [`move-vm-overlay-ext.md`](move-vm-overlay-ext.md) | The move VM's `0x2F` `OVERLAY_EXT` opcode and its 61 overlay-resident sub-opcodes (`FUN_801D362C`, dispatch JT `0x801CE868`). Split out of `move-vm.md`. |
| [`motion-vm.md`](motion-vm.md) | The two per-actor motion VMs: `FUN_8003774C` (pursue / patrol / face-target) and `FUN_80038158` (scripted motion + story-flag writes, bytecode in MAN tail-section 1). |
| [`run-rules.md`](run-rules.md) | Run-wide twists picked on the New Game rules screen: difficulty presets, New Game+, ironman, the in-engine randomizer (the patcher's planners from `crates/randomizer`, applied at the readers), Boss Rush. `engine-run-rules`; identity under the default rules. |
| [`gameplay-tweaks.md`](gameplay-tweaks.md) | Every patcher feature classified: avoided by construction, an engine switch (carried in `GameplayTweaks` or open), or patcher-only disc content; the carried switches and their tests. |
| [`vm-inventory.md`](vm-inventory.md) | Census of every VM-shaped subsystem (a bytecode dispatcher or a per-entity state-byte `switch`): what is decoded, ported, and reached by a live caller. "Five VMs" is an orientation, not the full list. |
| [`cutscene.md`](cutscene.md) | STR movies (game modes 26/27, Iki-bitstream MDEC decode, XA sync, `play-str`), the in-engine scripted opening / ending timelines on the field VM, and the field-to-battle transition. |
| [`battle.md`](battle.md) | Battle hub: scene loader `FUN_800520F0`, context struct, actor record, stage seats, monster record + archive (PROT 867), heap budget, per-frame actor passes; map of the sibling battle pages. |
| [`battle-command-flow.md`](battle-command-flow.md) | Command-flow SM `FUN_801D0748` (`ctx[+0x06]`): round prompt, D-pad command ring, commit log + confirm, target picker; the tutorial (967) and Cort boss-stage (968 / 969) overlays. |
| [`battle-action.md`](battle-action.md) | Battle action state machine `FUN_801E295C` (`ctx[+0x07]`): phase diagram, state table + per-state detail, cast cameras, turn cursor, effect script, port. |
| [`battle-action-exit-gates.md`](battle-action-exit-gates.md) | The state-`0x51` HP-bar settle gate and the state-`0x19` approach park: the two retail battle softlock classes and their root causes. |
| [`battle-action-helpers.md`](battle-action-helpers.md) | Helpers the action SM calls: range metric, escape roll, AI delegation + auto-combo, summon / cast dispatch, pose driver, voice cues, status word, overlay PRNG. |
| [`battle-action-queue.md`](battle-action-queue.md) | The action queue at `actor[+0x1DF..]`: byte alphabet, queue builder `FUN_801EED1C`, Tactical / Miracle / Super Arts, the no-input attack, damage per hit event, action validator `FUN_8003FB10`. |
| [`battle-stage-camera.md`](battle-stage-camera.md) | Battle stage (procedural ground grid, twice-drawn backdrop shell, stage-stream pick), the phase-scripted camera (`FUN_801D5854` framing cases, entry sweep) and the field-to-battle intro. |
| [`battle-actor-rendering.md`](battle-actor-rendering.md) | Battle actor rendering: assembled party meshes, monster mesh, staged-anim channel, tint passes, weapon trails, slow motion and after-image ghosts; both hosts' render bridges. |
| [`battle-hud.md`](battle-hud.md) | Battle HUD and screen chrome: placement table `0x80076C10`, widget-class table, per-phase sub-draw script, banners, badges, item window. Port `engine-battle-hud` + `engine-ui`. |
| [`battle-round-loop.md`](battle-round-loop.md) | One fight end to end: encounter roll + scripted `3E FF` entry, round bands, results sequencer, party wipe, `+0x16E` status bits, monster AI, Seru capture, the port's Field / Battle loop. |

| [`cast-module.md`](cast-module.md) | Slot-B cast / summon modules (PROT 0903..0966 at `0x801F69D8`): how an action reaches one through PROT 0898's three entry tables, image anatomy, `ctx+0x279` phase machine, tick ABI, damage shapes, camera, port. |
| [`inventory.md`](inventory.md) | One 256-slot bag at `0x80085958`, bounded by an **active window** (`gp[+0x2D2..+0x2D6]`) that collapses to one 128-slot half for a lone character. The "72-slot" figure is a cheat's display page. |

| [`world-overview-viewer.md`](world-overview-viewer.md) | The static-site `/world-overview/` WebGL viewer: AABB layout, distance-cue fog pass (per-Z scalar LUT + per-kingdom haze), MAN `0x7F`-sentinel bulk-terrain resolver, ocean tile + 13-frame CLUT animation, camera anchors. |
| [`save-screen.md`](save-screen.md) | Save-slot select + write flow (`FUN_801DC6B4`, menu overlay), the live game-state window at `DAT_80084140` the save block is composed from, its checksum, and the record screen behind the pause Status row. |

| [`level-up.md`](level-up.md) | Post-battle XP distribution, the per-level stat-gain table, and the banner. Retail applies XP + growth + level bump in overlay `FUN_801E9504`; port `engine-battle::levelup::LevelUpTracker`. |
| [`netplay.md`](netplay.md) | Multiplayer (the port's own; retail has none): wire protocol, lockstep and host-authoritative models, desync detection, AI seat handover, the relay and "host a world", security posture. Crate `legaia-netplay`. |
