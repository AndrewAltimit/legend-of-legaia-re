Settled reverse-engineering threads

Questions about how Legaia works that have an answer, and how firmly each answer is pinned. This is the archive half of the RE register: the live hunts are on open RE threads, and the readings that turned out wrong are on do not re-walk. This page is an index; every full write-up lives in the source document.

How to read this page

A thread is one question the project stopped to ask - why a boss battle freezes with the camera circling, where the party's battle models come from, which routine swaps the music. A thread is settled when it has an answer that can be pointed at: an instruction sequence, a runtime capture, or a measurement taken off the disc. resolved is a claim, not a warranty - which is what the evidence column is for.

Each area below is one table. A row gives the question, a one-line verdict, the evidence grade, and a link to the full write-up - every address, capture and correction - at its anchor in docs/reference/re-settled-threads.md. The areas run from the overworld inwards (world map, battle, field, text, animation, audio, boot, rendering) and end with the project's own instruments.

What an evidence grade means

Every thread is graded by what its stated evidence rests on. A thread citing more than one kind is graded by the weakest load-bearing claim - the one that breaks the conclusion if it is wrong.

GradeThe thread cites
disassemblyInstructions, addresses, opcode encodings, branch or store sequences read from the MIPS code. The strongest grade.
captureA runtime capture: a save state, an emulator probe, a write watchpoint, a trace, or a measurement taken off the disc.
decompiled-CGhidra's C output, a FUN_x(...) call signature, a Ghidra label, or a claim about store order / count / a boolean operator with no instruction behind it.
inferenceReasoning from surrounding facts, corpus absence, or analogy, with no direct evidence cited.

decompiled-C is the re-audit bucket, not a wrong-answer bucket. It marks a claim nobody has confirmed against instructions. Three shapes carry most of the risk: evidence citing a call signature or a funcs/<addr>.txt dump rather than instructions, any claim about store order or count, and any claim about which boolean operator a predicate uses. The catalogue of C-rendering artifacts is on Ghidra workflow.
