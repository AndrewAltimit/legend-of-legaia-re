Builds and debug features

Which Legend of Legaia discs exist and how their executables differ, and the build-level facts that matter when testing against a running game: the debug flags and their pad chords, the developer menus behind them and how to reach them in the port, and the RAM cells that published cheat codes poke. The anchor build is the North American retail disc, SCUS-94254; every address on this page is that build's unless a column says otherwise.

What differs between the retail executables

The French, German and Italian discs are container-identical to the USA disc - same PROT layout, same monster records - but their executables are not the NTSC-U engine with swapped text. Two gameplay differences:

  • No battle-load stat boost. NTSC-U boosts stats at battle load; the PAL executables do not.
  • Different battle spoils. PAL pays half the record's gold and the whole record's EXP; NTSC-U pays a quarter of the gold and three quarters of the EXP.

The JP original (SCPS-10059) matches the PAL behaviour on both counts, so both are NTSC-U additions. The Spanish disc and the EU English disc are unmeasured. Details: PAL localizations.

Cross-region testing priority: SCPS-10059 (original JP), then SCUS-94254 (anchor), then SCES-01752 (EU English).

Debug flags

Three flags in the same RAM page decide how much of the developer build the retail disc exposes.

FlagJP addressEffect
0x8007B8C2shifted by 0x1B90Dev / retail loader-path flag. Retail boots it to 1 (the store at 0x80015F08), selecting the PROT-index path; the == 0 path is the h:\PROT\FIELD\<stage>\… developer branch in FUN_800255B8 and its sisters.
0x8007B9B0-Overlay print flag, separate from the menu enable. The slot-A minigame overlays gate their printf-style readouts on it, several of them also on held pad bit 0x2; in the fishing overlay that pair also swaps the bite cadence for a debug value.
0x8007B98F0x8007D51FIn-game debug menu enable. Read as the high byte of the word at 0x8007B98C: the GameShark byte write 8007B98F 0001 makes that little-endian word non-zero (0x01000000), enabling every debug branch with one check.

All three have static writers in SCUS_942.54, reached $gp-relative ($gp = 0x8007B318) - which is why a cross-reference sweep that only looks for lui pairs reports none. Published GameShark codes also prove all three are writable at runtime.

CellWriter(s)
0x8007B8C2sh at 0x80015F08 (gp+0x5AA) - the retail boot-to-1 store
0x8007B98Csw at 0x8001D444 (clear), 0x8001D490, 0x8001D4B0 (gp+0x674)
0x8007B9B0sw zero at 0x8001D448 (gp+0x698)

Only the byte 0x8007B98F has no accessor of its own; it is reached as the top byte of the word at 0x8007B98C.

Debug pad chords

Once 0x8007B98F is set, these chords are live. The dispatcher is FUN_8001822C.

ChordEffect
SELECT + △Open the debug menu (item give, map change, stats, event flags, …)
SELECT + STARTStart the game in Debug Mode - the full-screen configuration tester in PROT 0971, reached as game mode 0 / CONFIG INIT (see boot)
R1 + R2 + ✕Coordinates debug overlay + free camera
○ (in coordinates mode)Dim lighting
▢ (in coordinates mode)Toggle the verbose overlay

Each frame FUN_8001822C reads the BIOS pad data at 0x800840F8 and builds a 32-bit button mask, _DAT_8007B850. If the debug word _DAT_8007B98C is zero it strips the upper 16 bits - the controller-2 / debug half - and that is the master gate. A large block guarded by _DAT_8007B98C != 0 then handles the chords.

Two consequences matter when driving the menu externally:

  • The chords are port-2 bindings. The same chord on port 1 is ignored.
  • The gate does not latch for the session. The debug word's only sw writer is the shared menu / title / save-init routine, which scene transitions run, so entering a scene can clear _DAT_8007B98C mid-session. Re-assert it rather than setting it once.

0x8007B7C4

Developer menus

SELECT + △ opens the in-game debug menu, but it is not one screen: it is four tools, each resident in a different overlay, that the retail debug branches reach.

ToolRetail entryLives in
Row list (MAP CHANGE, CAMERA, ENCOUNT, … 24 rows)FUN_801EAD98 draws it; FUN_801E9F64 applies each row's pad editsField overlay (PROT 0897) - the world map is a 0897-hosted mode, not an overlay of its own
EVENT FLAG editorFUN_801DBD04 value step; FUN_801DB8B4 / FUN_801DB8F4 list cursorField overlay (0897)
Character-parameter editorFUN_801D6E18Menu overlay (0899)
Equip commitFUN_801E5A08Field overlay (0897)

Controls. In the row list, Right steps the hovered row's value up and Left steps it down (the cursor lives at ctx + 0x9E; FUN_801E9F64 dispatches on cursor - 3). The two editors take the whole pad: Up / Down walk their own cursor and Left / Right edit the hovered value, read from the packed words _DAT_8007BB84 (newly pressed) and _DAT_8007B850 (held).

The character editor is worth knowing about even outside a debug build: at the end of every tick it runs a two-stage clamp over all four party records, whichever row is hovered. That clamp is the game's own statement of its stat caps; the records themselves are described on the save screen page.

Reaching the menus in the port

The Rust port carries all four tool families, and both play hosts mount them only behind an explicit opt-in:

Native play-window
Set LEGAIA_DEV_MENU=1 in the environment.
Browser play page
Tick the Dev-menu checkbox. It starts unchecked on every load and is neither persisted nor readable from the URL, so a shared link can never switch it on.
Square
Swaps the row list for the battle-records page, on both hosts.

With the opt-in taken, the row list is drawn and driven once a frame off the same packed pad words retail's developer code reads. Without it nothing runs and nothing is drawn, so a default build or page is unchanged.

The port's list carries the subset of retail's rows whose backing state the engine owns - MAP_CHANGE, ENCOUNT, EVENT_FLAG, PLAYER_PARAM, EQUIP - so that no row steps a value nothing reads. The missing rows need overlay-resident state the engine never loads. The clearest case is the flag-list table (DAT_801F2E94, stride 0xA with an 'X' sentinel): without it, the EVENT FLAG page edits a raw index only.

Character struct

Stride 0x414 bytes (1044), confirmed by file-offset deltas in ePSXe save states (Vahn / Noa / Gala). Four slots (Vahn / Noa / Gala / Terra the wolf) make a party block of about 4096 bytes - one PSX RAM page. Offsets are relative to the Level field, all u16 little-endian unless noted.

OffsetField
-0x2C / -0x2AHP max / HP current
-0x28 / -0x26MP max / MP current
-0x20..-0x16AGL / ATK / UDF / LDF / SPD / INT, current
-0x14 / -0x12HP / MP unequipped (base)
-0x0E..-0x04AGL / ATK / UDF / LDF / SPD / INT, unequipped (base)
+0x00Level
+0x55Moves-learned count (u8)
+0x56..Moves array (u8 IDs, contiguous)
+0x177Name (string)

"Current" stats are post-equipment; "unequipped" are the base values. The stat order is fixed across both blocks and all four slots. The full record is on per-character save record.

Money and inventory

24-bit (three consecutive u8 bytes, little-endian). Cap 0x00FFFFFF = 16,777,215 G.

One shared list, 2 bytes per entry [item_id, quantity]. Weapons, armor, items and Ra-Seru levels all live in it.

Move tables (Tactical Arts)

Slot 0x00 is the Miracle Art starter on every character (action constant 0x1B = Vahn's Craze / Noa's Ark / Biron Rage, gated by a story flag). Vahn and Gala carry their 14 regular arts at slots 0x01..0x0E. Noa's table runs to slot 0x10 with holes at 0x02 / 0x03 - her Hurricane Kick covers three on-disc levels through one slot - so her slot 0x0F is the ordinary art Acrobatic Blitz, not a Miracle Art. Mirror: legaia_art::tables.

Unused content

Useful as fixtures for validating extractors:

  • Unused enemies: index 78 ("Comm") and 140 ("Evil Bat") in the monster table.
  • Unused items: "Something Good" (sells for 50,000 G) and an unnamed accessory that forces Seru-only encounters.
  • Placeholder battle background: a graphic containing ぷろきおん in hiragana, loaded when a real battle background is missing.
  • Placeholder music: tracks copied from Alundra (the Zazan battle theme) and Wild ARMs (battle theme) sit in the SEQ / VAB data.
