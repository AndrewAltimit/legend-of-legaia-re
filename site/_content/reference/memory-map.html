PSX RAM map

The PlayStation has exactly 2 MB of main RAM, and everything the running game is - its code, the party's stats, the loaded scene, the story flags, the item bag - lives somewhere in that window. This map says what lives where: the big regions first, then the globals that matter, each with the function or cheat code that pinned it.

How to read an address

Every address on this site is a PSX virtual address: main RAM starts at 0x80000000, so 0x80084708 is byte 0x84708 into the 2 MB. A name like DAT_8007B83C is Ghidra's automatic label for data at that address, the way FUN_8003E4E8 labels a function (see key functions). Three things to know before you look one up:

  • The game executable is only the bottom of the picture. SCUS_942.54 loads at 0x80010000 and its data segment holds the persistent game state - character records, story flags, inventory. Most game logic, though, lives in overlays.
  • An address in the overlay window 0x801C0000+ is ambiguous on its own. Overlays are chunks of code the game streams off the disc into that window per game mode - field, battle, menu, title - and only one is resident at a time. The same address means different things in different modes, so rows in that range say which overlay they belong to.
  • 0x1F800000 is not main RAM. It is the 1 KB PSX scratchpad, and Legaia keeps hot per-frame state there - including the field-VM's transient flag word - so a flag a script tests may not be in the 2 MB map at all.

Rows carry their provenance: a FUN_ address, a ghidra/scripts/funcs/ dump path, or the cheat code that pinned them. Where a global's semantics are only partly understood the row says so - "exact semantics open" is a real value here, not an omission. The full row-by-row table is docs/reference/memory-map.md; this page carries the regions and the globals that anchor an explanation.

Game-mode state machine

The game is a loop over a mode - title, field, battle, FMV, menu - and one cell picks which mode runs next frame. These are the companions of the 28-entry × 24-byte mode-dispatch table at 0x8007078C (the table itself is on the boot page).

AddressTypePurpose
0x8007B83Cu16Next game-mode index (master mode selector). Drives the per-frame mode dispatcher: 0x02 field-launch, 0x03 field-run, 0x15 battle, 0x1A STR FMV. Title-attract underflow writes 0x1A. Also indexes the mode table, whose +0x14 param seeds the lower 16 bits of the field-VM flag word 0x1F800394 on each mode switch (FUN_8001DCF8).
0x8007B87CindexMode index rendered on the dev CONFIG / test screen; indexes the 0x8007078C table at stride 24 bytes (independently re-confirms the entry stride). Provenance ghidra/scripts/funcs/800188c8.txt.
0x8007B7ACmodeReads as the outgoing / previous game mode: the mode-entry prologue FUN_80016230 gates its whole field-state snapshot on == 3 (MAIN MODE) - "only preserve field state when the mode being left is the field". An inference from the guard's purpose, not a pinned writer; a write-watchpoint across a field→battle transition closes it.

Sound + audio path

The sound subsystem keeps a small cluster of path strings and state words in BSS - what tells the loader to look under sound\, which bank is resident, and the handshake that swaps one BGM for another.

PSX scratchpad (0x1F800000-0x1F8003FF)

The PSX has 1 KB of fast on-chip RAM here. Legaia uses the high end for per-frame state:

0x1F800314i16[]Inverted-Y mirror table (op 0x4C nibble-9 sub-E writes -words[i] here).

Overlay window (0x801C0000+)

The 256 KB overlay window is shared between several runtime overlays - only one is loaded at any time. Static analysis only sees what was loaded at the time of capture, which is why the repo keeps a separate import per overlay.

0x801CE818+Town / field / dialog (PROT 0897)Field VM (FUN_801DE840), MES renderer, inventory hub, MAIN INIT
0x801CE818+Battle (PROT 0898)Per-actor state machine, battle main dispatcher, effect VM cluster

Each mini-game likewise gets its own slab of upper RAM, loaded fresh when entered; the cheat-pinned cells (fishing tension at 0x801D9168, dance points at 0x801D53CC, and so on) are listed on the cheats page.

History: the "PROT 0896 @ 0x801C5818" menu-overlay base

An earlier attribution placed the menu overlay at PROT 0896, base 0x801C5818. That base was an over-read artifact of the superseded entry-size expression: the menu overlay is PROT 0899 at 0x801CE818, and live field captures hold an ISO9660 directory cache at 0x801C5818. Catalogued in do not re-walk.

Notes

  • Several globals that look like data (DAT_xxxxx in Ghidra) are actually pointers to runtime structs. The battle context at 0x8007BD24 is the canonical example - Ghidra types it as int*, code accesses it as (*ptr)[N].
  • The doc's full table also covers the world-map render pipeline and TMD/actor tables, the debug-flag cluster (including the 0x8007B8C2 dev/retail build-mode selector), and the runtime PROT TOC + asset chain globals - see the world map and asset loader pages for the mechanisms behind them.
