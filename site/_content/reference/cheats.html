Cheat databases

A GameShark (or Pro Action Replay) is a 90s cheat cartridge: each code it applies is literally a RAM address plus a value to write there every frame. That makes twenty-year-old community cheat lists an unusually rich source of ground-truth RAM addresses - "Infinite HP (Vahn)" only works if its target address really is where Vahn's HP lives, so every published code is a memory-layout fact someone verified on real hardware. This page explains where the corpus came from, how the codes are encoded, what they pinned, and how the engine replays them to check its own memory map.

At a glance

  • What it is: two public NTSC-U cheat lists, one in GameShark text form and one in Mednafen .cht form, committed under data/cheats/. They contain no Sony bytes - only labelled (address, value) pairs published since the late 1990s.
  • Why it matters: each code anchors a RAM offset independently of our own disassembly. The per-character record, the inventory array, the battle-actor pool and a handful of script-VM globals were confirmed this way.
  • What we built: crates/cheats parses both formats, classifies every address into a RAM region, and legaia-engine play-window --cheat-file applies the codes to the engine's own state - a cheat that stops applying is a sign the engine's memory map drifted.

Data files

  • legaia-ntsc-u.gs.txt - GameShark text dump format (one write per line).
  • legaia-ntsc-u.cht - Mednafen .cht format (TOML-shaped triples; multi-write effects join codes with +).

Both files describe the same effects in different on-disk encodings; cheat-tool diff compares them.

How a code is encoded

A GameShark code is eight hex digits of address and four of value. The high byte of the address is not part of the address at all - it is the operation prefix:

PrefixOperationExample
0x80u16 LE write80084816 0064 → mem16[0x80084816] = 0x0064
0x30u8 write300848A3 0000 → mem8[0x800848A3] = 0x00
0xD0conditional: if mem16 == value, execute nextD007B7C0 0100 (Select pressed)
0xE0conditional: if mem16 != value, execute nextE007B83C 0003

GameShark text dump

Each line of legaia-ntsc-u.gs.txt is one write, as a row of fixed columns:

ColumnMeaning
Rread/write classifier (always R - a cheat is a write)
Iencoding flag (always I)
1 / 2 / 4width in bytes
Lendianness (little)
0compression group (always 0)
80084816address, 8 hex digits, no 0x
64value, hex
rest of linedescription

When the prefix is 0x80 the parser uses the width column as ground truth (1 / 2 / 4) and rewrites the prefix accordingly - user-edited dumps occasionally desync the prefix from the column value.

Mednafen .cht

Each effect is one indexed triplet - cheatN_desc, cheatN_code, cheatN_enable. Multi-write effects join their codes with +; conditional codes use the same D0 / E0 prefix encoding.

Write taxonomy

taxonomy::classify_writes(addrs) buckets a set of changed RAM addresses by the region they fall in, de-duped and with per-bucket sample classifications. It flags writes that land outside every known data region (Unknown) or in the 0x8007Bxxx script-VM / build-flag scratch (ScriptVmGlobal - the band holding the 0x8007B8C2 build-mode selector and the debug-menu enable) - the anomalies a write tracer exists to surface. Pure and capture-free, so it is unit-tested with synthetic deltas. Wired end-to-end as mednafen-state write-taxonomy LEFT RIGHT, which diffs two save states at byte granularity and prints the per-region roll-up + attack-surface candidates.

In the release archive the built-in databases are embedded, so cheat-tool list / classify / extract-offsets need no path at all (modding guide).

What the corpus pinned, per category

Each bucket below is one RAM region the classifier knows. The interesting part is what the cheats in it tell us about the game's memory layout.

CharacterRecord

Per-character 0x414-byte record at 0x80084708 + slot * 0x414. Every offset is named on the save record page; the classifier's detail strings drop in via the field-name table there.

Inventory

Inventory array at 0x80085958, 2-byte stride alternating (id, count). The "Have 99 Items" cheat stamps 0x63 into every count byte across its 72-slot general-item page - the 72 is the cheat's span, not an engine bound; the live inventory window is 128 or 256 slots (RAM map, inventory subsystem). "Have Max Items" stamps 0xFF; "Item Modifier" zeroes the id byte.

BattleActor

Per-actor battle record at 0x800EC9E8 + n * 0x2D4. Pinned offsets:

OffsetFieldCheat
+0x14Chp_curr"Infinite HP" (per character)
+0x14Ehp_max(read by reader at battle init)
+0x150mp_curr"Infinite MP"
+0x152mp_max
+0x172hp_max_settled"Infinite HP" second site
+0x174mp_max_settled"Infinite MP" second site

The "second site" pair at +0x172 / +0x174 is the engine's record copy that survives FUN_80042558's per-frame stat aggregation clamp. Cheats target both sites to keep the value pinned across clamping.

0x8007B5FC"No Random Battles"Encounter step counter (cheat sets it to 0x377 to force or suppress a trigger)

CameraGlobal

0x8007B6F4 is the camera mode word. "Control Camera" and "Small Maps" cheats target it.

PartyMoney

The party-wide globals between the inventory header and the per-character records: 0x80084540 scene-name pool slot, 0x80084570 game time (u32), 0x80084594 party-member count, 0x80084598..0x8008459A member ids and the Noa / Gala join gates, 0x8008459C gold (u32), 0x800845A4 / 0x800845A6 casino coins, 0x800845DC scene-name mirror.

WorldStoryFlag

A region bucket for the story-flag block at 0x80085600..0x80085800 - outside the per-character records and outside the inventory window. No cheat in the shipped corpus lands in it. The one candidate, "Access All Towns When You Use Door of Wind" at 0x8008575C / 0x8008575E (a 32-bit visited-towns bitmask), is claimed first by the script-VM-global arm, which names those two cells story_flag_door_of_wind_lo / _hi, so cheat-tool list reports it as ScriptVmGlobal. That is arm ordering inside classify_address, not a statement about the cheat.

Minigame

Mini-game scratch RAM. Fishing uses 0x801D9168 / 0x801D9274 / 0x801D9298 / 0x801D91CC for tension / casting power / life / fish id; Baka Fighter 0x801DBFC4 / 0x801DBFF0 / 0x801DC06C; dance points 0x801D53CC; slot machine 0x801D3CAC. These are recorded as citations only - the engine's minigame ports do not consume them.

FieldVmCollision

The "Walk Thru Walls" cheat patches four collision-state cells in the field overlay: 0x801D078C / 0x801D071C / 0x801D065C / 0x801D06BC. Each is a 1-byte gate the field VM consults during movement; setting them all to 0x06 disables the collision check.

ScratchActiveActor

0x8007A6BC is shared scratch for the currently-acting character. Every "Infinite HP / MP" cheat hits this cell first - the runtime reads it during the per-actor frame tick before applying back to the per-record copy. Useful to know when chasing post-battle stat-leak issues.

CodePatch

A handful of cheats patch running code rather than a RAM cell. Three write 0x2400 to an instruction's upper halfword (addr % 4 == 2), rendering it addiu $zero, $zero, imm - the GameShark nop idiom:

  • 0x8004309E - "Infinite Items All Slots" nops the count-decrement instruction.
  • 0x8004390E - "Remove Vahn's Chest" nops a draw-call site.
  • 0x8007EA96 - "Maxed HP for All Characters". This address is past the end of the SCUS_942.54 image (text spans 0x80010000..0x8007B800), so whatever it patches is not SCUS code, even though the bucket is CodePatch.

One is a different shape and does not write 0x2400 at all: 0x800422F4 - "Bought Any Item / Find Items You Will Get 99 Quantity" writes 0001. The word there is bne r2, r0, +2 inside the inventory-add clamp (slti r2,r2,100 / addiu r3,99 / sb); shortening the displacement makes the clamp always run. All of these are useful Ghidra anchors: the patched instruction addresses give callsite hints the LUI+ADDIU resolver wouldn't.

Runtime applier

legaia-engine play-window --cheat-file <PATH> parses the file via legaia_cheats, applies every entry once at boot via legaia_engine_core::cheat_applier::apply, and dispatches each write through the ram_map registry to the appropriate World / CharacterRecord field. Conditional codes are treated as always-true by default (--cheat-strict honours them, which skips every cheat that gates on a button press the engine doesn't emulate).

Cheat report (49 entries, 96 writes; 71 applied, 25 unmapped, 0 unknown):
  ok    Infinite HP (Vahn)............... 4/4 writes
  ok    Infinite Gold (Never Glitchy).... 1/1 writes
  skip  Walk Thru Walls.................. 0/4 writes
  ...

A skip line means every write in the entry landed in a RAM region the ram_map registry does not map onto engine state (for Walk Thru Walls that region is FieldVmCollision); part marks a mixed entry.

Use this to validate that a code change keeps the same set of cheats applying. If a previously-applying cheat starts failing, either the engine field it targets was renamed (update ram_map), the engine no longer exposes the field (update WorldField), or the cheat database had stale data (update the citation in the format doc).
