Pack format (inside TIM_LIST and TMD chunks) Confirmed

The simplest way Legaia bundles several assets into one blob: a count, a table of offsets, then the assets packed back-to-back. When a scene needs a dozen textures or a handful of meshes at once, this is the shape they arrive in - the data payload of a TIM_LIST or TMD chunk inside a DATA_FIELD streaming container. There is exactly one pack format on the disc; the "standalone TIM-pack" and the "field-pack" are this same pack read from behind a 4-byte chunk header, as the last section shows.

Overview

Inside a streaming chunk the bytes say nothing about what they are - the chunk header already said "a list of TIMs" or "a pack of meshes". So the pack itself is minimal: how many members, where each starts, then the members. Offsets count 4-byte words from the start of the pack data, and there is no per-pack magic.

Layout

+0x00countu32
+0x04word_offset[count]u32 × count
word_offset[0] × 4members, back to backto chunk end

Each word_offset counts 4-byte words from the start of this pack's data (not from the end of the table), and members sit on the 4-byte word grid with no other padding rule.

Sub-asset i lives at byte range [word_offset[i] * 4 .. word_offset[i+1] * 4), with the last sub-asset ending at the chunk's end.

Example

A TIM_LIST chunk header followed by a 2-TIM pack (a TIM is the PlayStation's standard texture format):

6c 02 01 01chunk header: type 0x01 TIM_LIST, size 0x01026Cu32
02 00 00 00count = 2u32
03 00 00 00offset[0] = 3 → byte 12u32
8b 20 00 00offset[1] = 0x208B → byte 0x822Cu32
pack +12TIM 0, then TIM 1…

Word offset 3 is byte 12 - exactly the size of the count word plus the two-entry table, so the first member starts right after the header.

One format, two readers

A hex dump of a scene's texture entry looks like a second pack format: a marker byte 0x01 at +3, a count at +4, and member offsets that need an extra +4. It is not a second format. Those first four bytes are a DATA_FIELD chunk header, (TIM_LIST << 24) | payload_len, and what follows is an ordinary pack. The older prot::timpack reader simply reads the pack with the header still attached, which is where both its marker test and its +4 come from. The "field-pack" word 0x01059B84 is the same chunk header on town01's texture pack.

Use legaia_asset::pack on a pack that starts at offset 0 (a chunk payload), and prot::timpack - or skip the 4-byte header first - on a whole chunk. legaia_asset::field_pack::scene_pack locates the chunk-headered scene pack inside a CDNAME block. The effect bundle (0x02018B0C) is a genuinely different layout.

How we know

The chunk dispatcher's type-0x02 arm walks the count and word-offset table and hands each member to the TMD handler, which consumes it at word_offset[i] × 4 with no added constant.
