Expansion packs: items, equipment and shops

items.toml adds new consumables and equipment to an expansion pack, groups equipment into sets with bonuses for wearing them together, and opens the pack's own shops. Every hook is the identity with no pack active (or a pack with no items): nothing is compiled, no stat changes, no alias is lent, and a save carries no item record.

Where pack items live

Retail's item id is a u8, and the static item table names 250 of its 256 ids. The six blank ones are 0x00 ("no item") and five cut slots, 0x12, 0x1A, 0x52, 0xB9 and 0xFD. A pack item cannot take a retail id without displacing a real item, and five spare ids are too few for a gear set, so pack items live in their own store, keyed by their items.toml key.

Neither retail structure ever holds a pack item, which keeps a retail save's bytes and a no-pack session untouched. The retail Items and Equip screens therefore do not list pack items; the pack item screen does.

Battle aliases

A fight needs a u8 for the pack items in it: a drop byte, a steal entry, an Item command row. For one fight the engine lends the five cut ids to those pack items - each pack drop and steal of the seated monsters first, then each battle-usable pack consumable held - with a catalog entry each, so the retail drop roll, steal, Item command, handler and results window all work on them unchanged. A grant or consume of an alias goes to the pack bag. At most five pack items take part in one fight.

items.toml

[items.rebirth_blade]
name = "Rebirth Blade"
kind = "weapon"
icon = { kind = "item", id = 0x27 }
characters = ["vahn"]
attack = 112
set = "rebirth"

[items.phoenix_plume]
name = "Phoenix Plume"
kind = "consumable"
price = 12000
effect = { kind = "revive", percent = 50 }
all_party = true

[sets.rebirth]
bonuses = [{ pieces = 2, attack = 10 }, { pieces = 4, passives = [0x24] }]

[[shops]]
id = "tower_armory"
stock = ["phoenix_plume", 0x79, { item = "rebirth_crown", requires = { bosses = ["iron_regent"] } }]

Each effect is a retail item handler: heal_hp / heal_mp (an amount or full), revive (a percent of max HP), cure (one ailment), cure_all, damage, and as_item, which runs a retail item's own handler (a stat raise, a battle buff, Fury Boost). A set tier applies while one hero wears at least pieces of the set, and tiers stack. A shop row is an item reference or { item, requires, price }: requires lists it only while the quest-prerequisite gate holds.

Item references

Everywhere a pack names an item it writes an ItemRef: an integer (0x79, a retail id), an item coordinate ({ kind = "item", id = 0x79 }), or a string ("rebirth_blade", a pack item). Drops, steals, boss and level rewards, quest rewards, collect_item objectives and shop stock all take it.

Runtime

  • Grants and counts. A reward lands a retail id in the retail bag and a pack item in the pack bag with a Got X toast; a collect_item counts the bag its reference names.
  • Wearing. A pack item empties its retail byte (the retail item there goes to the bag); a retail item later equipped over it sends the pack item back.
  • The stat fold. The battle seed adds worn pack gear as retail gear: ATK into the slot's per-swing byte, UDF / LDF / SPD into the seeded lines, passives and set tiers into the record's ability bits. INT stays menu-only, as retail head gear's does.
  • Look. A worn pack item's icon fills its empty byte for the battle mesh, swing costs and command chips.
  • Consumables. In battle, held pack consumables join the Item command under their aliases; in the field, the bag's Items tab uses them.

The item screen

The pack item screen owns the frame under SceneMode::Expansion, as the card screen does, so both play hosts draw it from one composition. A map's { kind = "shop" } trigger or a shop NPC opens a counter (Buy / Sell); the Journal's Items page opens the bag (Items / Gear). The Gear tab's member step shows what the slot holds now and the five equipment-fed stats before and after, green up and red down.

Saves

The pack bag and the worn gear are pack progress: they save, park and adopt with the pack's LXP1 block as tail record 4 (u16 bag entries of key + count, then u16 worn entries of hero + byte + key). The record is written only while something is held or worn, and a save made with no pack carries no block at all. Without the pack a worn pack item's retail byte stays empty; it is back when the pack is.

Validation

Errors: an empty or over-long name, a stat outside -255..=255, a passive past 0x3F, an element past 6, an unknown set, a consumable with no effect or usable nowhere, a heal with no amount, a bad revive percent, an icon or as_item that is not an item, a shop row naming an unknown pack item, a map shop naming no shop. Warnings: equipment with no icon, misplaced fields, a set with one member, a pack row with no price.

Limits

  • At most five pack items take part in one fight.
  • Pack gear is worn by the three heroes only.
  • The retail Items and Equip screens show no pack items; a worn pack item's slot reads empty there.

Rebirth's gear

The flagship pack's gear is set against retail's endgame Ra-Seru set from the static equipment table. Each Rebirth piece is about 12-15% above its Ra-Seru twin:
