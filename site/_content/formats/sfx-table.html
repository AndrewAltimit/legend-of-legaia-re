Sound-effect descriptor table Confirmed

The menu blip when you move the cursor, the thud of a Tactical Arts hit, the chime of a level-up: each is a sound-effect id, and each id is one 8-byte row in a 100-entry table baked into SCUS_942.54, the game's main executable. The row says which instrument in a loaded VAB sound bank to trigger and how many SPU voices (hardware channels) to fan it across. The interesting byte is the fifth one: it looks like a mixer channel, and it is, but it also picks which bank the cue plays out of - four fixed banks are open at once in retail, and a cue names its own. Ids ≥ 0x200 come from a per-scene bank instead of this table.

Record layout

How to read a row: sound_id indexes the table at an 8-byte stride (DAT_8006F198 + sound_id*8); the five live bytes name a program (instrument), tone, note level, voice count and category. The field names are the designer's own, recovered from a runtime debug format string of the form p / t / l / n / id.

OffsetSizeFieldMeaning
+01p programProgram / VAG index - selects the bank's program-attr entry
+11t toneTone / ADSR-region base; a multi-voice cue uses consecutive regions (+i per voice). Named by index, not resolved by key range (below)
+21l noteNote-level voice attribute (MIDI-ish, clusters near 60)
+31n voicesLow 5 bits = voice count; bit 0x20 = sustained / continuous mode
+41id categoryPicks the 12-byte mixer record at 0x80091508 + category*12, and through its +8 the VAB slot the cue keys (below)
+5..73-No observed runtime reader; zero across the table

The runtime readers gate on sound_id < 0x200, but that is a bound, not the size: only ids 0x00..=0x63 are real descriptors (every one populated, voice count 1..=3, trailing bytes zero). Id 0x64 onward is unrelated rodata, so the true extent is 100 entries.

Ids ≥ 0x200 - the current bundle's record 0

The gate's other arm is not a second fixed table. Both readers resolve it out of the sound subsystem's current-bundle slot _DAT_8007B8D0:

id <  0x200:  desc = DAT_8006F198 + id*8              ; this page's table
id >= 0x200:  desc = _DAT_8007B8D0 + offsets[0]       ; the bundle's record 0
                     + (id - 0x200)*8

FUN_800250D4 (0x800250F4..0x8002514C) picks the arm with slti v0,a2,0x200, applies the bundle header's +0x02 word to reach offsets[0], and adds (id - 0x200) * 8; FUN_80016B6C does the same. Which bundle sits there is whatever loaded last: FUN_8001FA88 puts bse.dat there at init, and the field asset loader repoints it at the scene's prescript bundle on every field load (FUN_8001F7C0). So in field mode the ≥ 0x200 bank is the scene's own prescript record 0, sized per scene (jou reserves 96 rows and populates 40; rugi carries 21) - neither bse.dat nor a .dpk / monster.snd. Why that record must not be spawned as a move-VM stager is on the audio page's ambient-fx material; the init-time occupant is bse.dat (sound-driver formats).

Consumers - the ring and the voices

FunctionRole
FUN_800250D4(sound_id, voice)Per-actor SFX trigger (from the actor tick FUN_80021DF4). Uses only the voice count, SpuKeyOn-ing (FUN_800653C8) that many consecutive voices.
FUN_80016B6CPer-frame cue-ring drainer. Walks the 4-slot ring, then programs voice_count voices via FUN_80065034 (the libsnd SpuSetVoiceAttr analogue: program +0, region +1 +i, attr +2, channel from +4).

The SPU programming itself is libsnd and out of clean-room scope; what is portable is the data.

The ring is two arrays - a scheduled one-shot, not a queue

DAT_8007B6D8[4] (i16 cue ids) has a sibling DAT_8007C338[4], a u32 countdown in vsyncs per slot. Three functions touch them in a fixed per-frame order:

  • FUN_8001698C ages: a slot with timer zero has its id cleared to -1; a non-zero timer is decremented by the adaptive frame step DAT_1F800393 and floored at zero (two stores, so a slot cannot skip past zero).
  • Producers: FUN_80035B50 writes id plus timer = 0 into the cursor slot gp+0x158 and advances round-robin over the four. The dispatcher FUN_8004FCC8 (the move-power +0x0d cue path) stores id - 1 for id < 0x40.
  • FUN_80016B6C drains: a slot plays only when its timer is exactly zero and its id is still ≥ 0.

So a cue armed with timer N plays on the frame its countdown first reads zero, in vsyncs (at the field cadence floor of 2, timer = 4 plays after two game ticks), and a fifth pending cue replaces one. The ring value is the descriptor index: overlay code that writes the ring directly (the Baka Fighter overlay's 9 / 0x20 / 0x21 / 0x37 stores) is writing ids as-is. Port: legaia_engine_audio::sfx_ring.

The channel gate is the 12-byte mixer record at 0x80091508 + channel*12: +0 a VabHdr pointer, +8 the VAB slot id handed to FUN_80065034, +0xB an enable byte (zero skips the cue before any voice work). DAT_80091510 / DAT_80091513 are record 0's +8 / +0xB, not two byte arrays. While _DAT_8007BA88 is non-zero every cue is forced onto channel 6.

Category is a bank selector - four banks open at once

FUN_80065034 passes the mixer record's +8 to FUN_80068b98(vab_id, program), which rejects it unless < 0x10 and the per-bank open byte _DAT_801CE368[id] == 1, then repoints the libsnd current-bank globals (_DAT_801ce33c header, _DAT_801ce334 ProgAtr, _DAT_801ce340 VagAtr) at that slot before reading them. The identity "category = slot" is written by the sound-system initialiser FUN_8001D424 (+8 = record index for all 16 records), not merely observed. So a cue is not keyed against whichever bank the BGM sequencer left open.

That is why "the SFX bank is the scene's music VAB" is a half-truth: it is exactly true of slot 1, and no descriptor keys slot 1. A bank reaches a slot through one call pair - FUN_8001FC00(raw_toc_index, category, buf, append, len) streams the entry, FUN_8001E54C(category, buf, len) installs it via SsVabOpenHead / SsVabTransBody with the SPU address from the per-slot table at 0x800917B0. Raw TOC indices run two above extraction indices (CDNAME numbering).

Each pin carries a structural check. PROT 0868 is a byte match: a live field state's slot-0 VagAtr program-0 page occurs verbatim at VAB offset +4. PROT 0876 holds 30 VAGs for the 30 category-6 descriptors, with 29 of them naming a program in its populated set 1..=7. PROT 0889 is a one-program bank whose only populated slot is program 10 - exactly what cue 0x50 names, loaded by the same function that fires it. Descriptors 0x40 / 0x41 name program 10, which 0869 lacks and 0875 populates - the DAT_8007BD11 == 4 alternate. CDNAME labels read battle_data for 0868 and monster_data for 0869 - a label is a hint.

The slots are aliased in pairs

FUN_8001D424 assigns header buffers from one base and four pairs share one: records 0/10, 1/5, 2/6, 8/11. FUN_800265E8 installs the per-slot SPU addresses and the same pairs share a base there:

So the field bank (slot 6) and the class-2 battle bank (slot 2) are the same physical region, refilled per mode - they can never be resident together. The gaps are allocation, not enforcement: PROT 0869 is 3 808 bytes larger than the gap below slot 3, and a bank overruns its neighbour whenever that neighbour is closed. The catalogued save states show the partition directly in _DAT_801CE368: field modes open 0, 1, 3, 6 (+5), battle opens 0, 1, 2, 7 (+5, 8); slot 2 is never open in the field, slot 6 never in battle, and slot 11 in none (the reward path loads it later than any state was taken).

History: slots 6 / 11 "unpinned" and the single-bank port

Slots 6 and 11 were once listed as unpinned; PROT 0876 and 0889 are now byte-pinned as above. Before that, both viewers and the engine staged a single resident bank (the class-2 one) and fired every cue through it. That fails quietly: both PROT 0868 and 0869 carry a one-VAG-per-semitone UI key map at program 0, so a category-0 id fired through the class-2 bank resolves to a sibling sample - a genuine retail blip, roughly twice as long and a fifth lower because 0869's center bytes are authored higher. Peak, duration and "did a voice key on" all pass; only the source PROT entry differs. That was the thump the browser play page's pause menu made. See do-not-re-walk.

What a port has to get right

A cue names its tone by index, not by key range

The SFX fire path and the sequencer's note-on differ. FUN_80065034 is handed the descriptor's fields directly - program, region index +1 (+i per voice), note +2 - so the tone is an explicit index into the program's tone list, not resolved by asking which tone's authored min..=max window contains the note. Several retail cues have a note outside their tone's window (the menu cancel 0x37 is program 0 / tone 5 / note 64 against a [65,65] window), so a key-range lookup renders silence for them. The engine models the SFX shape with VabBank::play_tone alongside play_note for the sequencer.

Retail does pitch the UI cues down

Program 0 of the class-2 bank is a purpose-built key map - one VAG per semitone, single-note windows min == max == 60 + i matching the UI descriptors' notes 1:1 - with center bytes at 79..=88 against notes 60..=69, so every UI cue keys 12..26 semitones under its centre. That is the authored sound: pitch is 0x1000 * 2^((note - center + fine/128)/12), unity at note == center, with no sample-rate factor (audio). A port that also multiplies by 22050/44100 keys them an octave lower again. The pause menu itself keys these ids in the slot-0 bank, PROT 0868, whose program 0 has the same shape over its own VAGs (center 72..=90, a shorter, brighter blip); the class-2 copy is the one the minigame overlays key directly.

The UI ids are global, not the duel's

0x20 confirm / 0x21 cursor / 0x23 disabled-row buzz / 0x37 cancel are written by the SCUS-resident list kernel FUN_80032A44 that pages every pause-menu list window (field menu). The Baka Fighter overlay is a co-user, not their source.

Walking fires no cue - retail has no footstep sound

A probe watching both ring producers, the dispatcher, the per-actor trigger, the voice programmer and the four ring slots at once, run twice on one state (standing vs D-pad held) for the same vsyncs, sees nothing fire while walking a house interior or the overworld - not one FUN_80065034 voice program. The one walk that produces cues produces exactly two, 0x2E then 0x2F, hundreds of vsyncs apart from the field VM's script SFX arm (op 0x36) as the player crosses triggers. The per-frame field cadence FUN_80018DB0 never fires its step gate (_DAT_8007B8A4 stays at 2), and its two output bytes are pad-report bookkeeping, not cue traffic. A port that wants a footstep has to author one. see ghidra/scripts/funcs/80018db0.txt, 80035b50.txt, 800250d4.txt.

SPU budget - both pinned banks in one region

The engine stages slots 0 and 2 together, so its reserved SFX region must hold both and the BGM region is what is left of the console's 512 KiB of sound RAM:

Every VAG is already a multiple of the 16-byte ADPCM block, so 2 592 bytes stay free. One step larger silences music that plays today; one step smaller does not fit both banks. Both hosts use the same constant. The 31 category-6 / 11 descriptors fall back to the class-2 bank - a residency limit, not a gap in the map: retail never sums the four banks because slot 6 is slot 2's region, so a host that wants the field cues right reloads the shared region on the field / battle transition rather than widening the reservation.

Provenance and parser

Decoded from the disc and cross-checked byte-for-byte against live save-state RAM: the window at 0x8006F198 in a catalogued mednafen state parses to the identical 100 descriptors. The two cue ids the engine's default bank references resolve to 0x1A = program 3 / tone 0 / note 67 and 0x4C = program 3 / tone 8 (voice count 2). The open bank in slot 1 varies per scene (13 distinct VABs across the captures) and for a music_01 scene is byte-identical to the disc VAB apart from the runtime-patched ProgAtr +8..15 pointer.

legaia_asset::sfx_table::SfxTable::from_scus resolves the table from a SCUS_942.54 image (PSX-EXE t_addr → file-offset map, the same resolver the item-name table uses); from_table_bytes parses a raw RAM window. SfxDescriptor exposes voice_count() / sustained() / is_active() / vab_slot(). The routing law lives beside it: slot_for_category, prot_index_for_slot (None only for the variable slots), prot_index_for_category, SLOT_BANKS, PINNED_SLOT_BANKS, spu_base_for_slot + SLOT_ALIASES, FALLBACK_VAB_SLOT, and SfxTable::cue_slots / slots_used.

Disc-gated tests: sfx_table_real (layout + category histogram), sfx_table_live (live RAM → SfxBank::from_descriptors), sfx_cue_resident_bank (routed cues key a voice via the tone-index path and both banks pack in the region), and the web viewer's play_sfx_channel (a category-0 and a category-2 cue resolve to different PROT entries). The site's media cue player walks SCUS → this table → the bank each category names → a one-shot through the clean-room SPU. Source of record: docs/formats/sfx-table.md.
