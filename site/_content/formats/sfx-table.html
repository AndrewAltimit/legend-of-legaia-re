Sound-effect descriptor table Confirmed

The blip when the cursor moves, the thud of a Tactical Arts hit, the level-up chime: each is a sound-effect id, and each id is one 8-byte row in a 100-row table baked into the game's main executable. A row names an instrument in a loaded VAB sound bank, how many hardware voices to use - and, through its category byte, which of four open banks the cue plays out of.

Record layout

A cue id indexes the table at an 8-byte stride. The field names are the designer's own, recovered from a runtime debug format string (p / t / l / n / id).

+0p programu8
+1t toneu8
+2l noteu8
+3n voicesu8
+4id categoryu8
+5zero3 B
FieldMeaning
p programProgram (instrument) index in the bank
t toneTone index within the program; a multi-voice cue uses consecutive tones (+i per voice). Named by index, never resolved by key range
l noteMIDI-style note (clusters near 60)
n voicesLow 5 bits = voice count (1..=3 in retail); bit 0x20 = sustained mode
id categorySelects a 12-byte mixer record, and through it the VAB slot the cue keys (below)
+5..7Zero across the table; no reader

Row 0x64 onward is unrelated rodata (a dev-path string), so the readers' < 0x200 gate is a bound, not the table size.

Which bank a cue plays from

Four fixed banks are open at once and each category keys exactly one of them. The other open slots hold variable banks (scene music, side-band, monster sounds) that no descriptor keys - "the SFX bank is the scene's music VAB" is true only of slot 1.

Slots share sound RAM in pairs

The field bank (slot 6) and the class-2 battle bank (slot 2) occupy the same physical SPU region, refilled per mode, so they are never resident together. Field modes open slots 0, 1, 3, 6; battle opens 0, 1, 2, 7. The battle mode init closes slot 6 and clears the field-bank latch 0x8007BAFC (so do the minigame warp and field-VM op 0x36 sub 3); the next field init sees the latch clear and reloads PROT 0876. A cue whose slot is closed is skipped, not rerouted.

Firing a cue

Two readers consume the table: the per-actor trigger (used by the actor tick) and the per-frame cue ring drainer. The SPU programming under them is PlayStation library code; what is portable is the data and the ring.

The ring: four scheduled one-shots

  • Four slots, each an i16 cue id plus a u32 countdown in vsyncs. A producer writes the id with timer 0 into a round-robin cursor slot; a fifth pending cue replaces one.
  • An ager decrements every timer by the adaptive frame step and floors at zero; a slot at zero with no id becomes -1.
  • The drainer plays a slot only when its timer is exactly zero and its id is still ≥ 0. A cue armed with timer N plays on the frame the countdown first reads zero.
  • Who writes it in the field: field-VM op 0x36 (sub 0 pushes a cue id, sub 4 sets its delay in vsyncs - scripts pair them) and the motion VM's op 0x09. Both pass the id straight from bytecode, static ids and per-scene ids ≥ 0x200 alike.
  • The ring value is the descriptor index; overlays that write the ring directly write ids as-is. The move-power cue path stores id - 1 for id < 0x40.

The side-band bank a script selects

Category 3 keys the side-band slot, and field-VM op 0x36 sub 1 picks which bank fills it: a request id 2000..=2999 streams the vab_01 block's entry id - 2000 into slot 3, ≥ 3000 streams id - 3000 into slot 6, and 0x1000 parks the request without loading anything. Shipped scripts use only those three forms.

The mixer record's enable byte (+0xB) skips a cue before any voice work; while a global override is set every cue is forced onto channel 6.

What a port has to get right

  • Tone by index. The fire path hands the descriptor's tone index straight to the voice programmer. Several retail cues carry a note outside their tone's key window (menu cancel 0x37: tone 5, note 64, window [65,65]), so a key-range lookup renders silence. Engine: VabBank::play_tone beside the sequencer's play_note.
  • UI cues are pitched down on purpose. Program 0 of the UI banks is a one-VAG-per-semitone key map whose center bytes sit 12..26 semitones above the descriptors' notes. Pitch is 0x1000 × 2^((note - center + fine/128)/12) with no sample-rate factor; a port that also multiplies by 22050/44100 drops another octave.
  • The UI ids are global. Confirm / cursor / buzz / cancel are written by the SCUS list kernel that pages every pause-menu window; the Baka Fighter overlay is a co-user, not their source.
  • There is no footstep sound. A probe over every producer, the trigger, the voice programmer and the ring sees nothing fire while walking; the only walk cues (0x2E, 0x2F) come from field-script triggers. A port that wants a footstep has to author one.
  • Stage the right bank. A single-bank port fails quietly: a category-0 id fired through the class-2 bank resolves to a sibling sample - a genuine retail blip, twice as long and a fifth lower.
SPU budget: both pinned banks in one region

A port that stages slot 0 plus the current mode's slot-2 / slot-6 bank together has this much sound RAM left for music out of the console's 512 KiB:

One step larger silences music that plays; one step smaller does not fit slot 0 plus PROT 0869. Slot 6 is slot 2's region in retail, refilled per mode: PROT 0876 (the field bank) in the field and on the world map, PROT 0869 in battle, a minigame's own bank in its mode. A cue whose slot is closed is silent, as retail's drainer skips it.

One bank does not fit that window: the dance hall's (PROT 1231). Retail overruns into slot 3's closed base; the port has slot 0 below and the top of SPU RAM above, so it lays the overflow in the BGM region's free tail instead (a voice addresses each sample on its own, so a bank need not be contiguous). That half is a borrower: a track that reaches it drops the bank, and the director re-stages it once the free tail moves.

Ids ≥ 0x200: the current bundle's record 0
Cue idDescriptor address
< 0x200table + id*8 - this page
≥ 0x200bundle + offsets[0] + (id - 0x200)*8 - the current sound bundle's record 0

Both readers resolve the high arm through the sound subsystem's current-bundle pointer, and it has two occupants. In the field the loader repoints it at the scene's prescript bundle on every scene load, so the high bank is the scene's own record 0, sized per scene (jou reserves 96 rows and fills 40; rugi carries 21). In battle it is bse.dat (sound-driver formats) - loaded at battle-scene setup, not at boot: its one caller anywhere on the disc is inside battle init FUN_800513F0.

One column is not static in battle. Before enqueueing a cue the battle cue router FUN_8004FE5C overwrites byte +4 (id, the category) of record[cue_id - 0x200] from a per-actor byte, reaching the bank through its own saved pointer gp+0x678 rather than through the current-bundle slot. So a live cue's VAB slot is chosen by the actor that fired it, and the authored category is a default.
