Patching a sealed disc

A randomizer seed changes what a chest holds, what a monster drops, where a door leads and what a shop sells - on a retail disc that ships no source, no SDK and no extension points. Every one of those changes is one of seven injection techniques, and the techniques form a ladder: from same-size byte edits, through editing inside compression and rewriting bytecode, up to hand-assembled MIPS hosted in an overlay's dead space. This series walks the ladder one rung per page.

The idea in one box
The disc is never resized. Almost every edit overwrites bytes in place and re-encodes the sector's error-correction fields, so no file offset or table of contents ever moves. Where an edit's meaning forces a length change (a door name), the scene's script is rebuilt and recompressed into the same footprint - or the scene is skipped. New behaviour is hand-written MIPS parked in bytes the game never reads, reached by a two-instruction detour.

The technique ladder

Seven techniques in ascending order of what they let you change - and of how much reverse engineering each demands before the first byte can move.

Three capabilities the preservation track never needed

The asset-preservation half of the project only reads the disc. Writing one back needs three pieces, and every mod stands on them.

CapabilityModuleWhy
LZS encoderlegaia_lzs::compressRetail ships only a decoder. Greedy LZSS, slightly looser than Sony's packer, always accepted - Legaia LZS.
Sector write-backlegaia_iso::writeA CD sector carries error-correction fields over its payload; overwrite the payload and they must be recomputed or the sector reads as damaged - disc geometry.
Disc bridgedisc::DiscPatcherMaps a "PROT entry N, offset K" edit to the sector it lives in through the PROT.DAT table of contents.

The editing model: same-size, except when it can't be

  • In place. Each target sits in a fixed slot with slack (a monster's 0x14000-byte slot) or is a fixed-width table field, so the patch is a byte overwrite plus a sector re-encode. No offset anywhere moves.
  • Relocate. When the edit itself changes a byte count, the MAN relocation engine rebuilds the decompressed script, fixes every disturbed offset, and recompresses into the asset's original footprint - or leaves the scene vanilla.
  • Either way the disc's total size never changes, which is what makes a PPF patch a complete description of the edit.
