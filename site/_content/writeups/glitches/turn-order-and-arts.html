Turn order, double attacks and kicks

Four oddities players have reported, traced to the game's own code: the Spikefish Flute cancelling enemy turns (the Koru flute glitch), the War God Icon sometimes giving one attack string where two are expected, Side Kick missing floating enemies even with War God Boots, and a level-3 dance special swallowing the next one. Each section says what happens in plain words first, then gives the addresses so other reverse engineers can check it.

How to read this page
Everything here is read from the USA release's executable, its overlays and the data on the disc. Three of the four cases were also watched in a running game, and each section says exactly how: the dance lock with scripted button presses and nothing written to memory; the War God Icon refusal and the flute's early round end on poked states, meaning some memory values were written by hand to set the situation up, and the section lists which. Side Kick is read from the code and data only. Addresses are for the USA build (SCUS_942.54) unless a table says otherwise; ctx means the battle context block, found through the pointer at 0x8007BD24.

The Spikefish Flute cancels enemy turns (the Koru flute glitch)

Reported as
In a boss fight the flute skips the party's remaining turns, and for every party member who already acted it also cancels an enemy turn, slowest enemy first. Against Koru it can stop Dead End Crisis for good (community report).
Cause
The flute's turn-skip adds one to the round's turn count per living party member instead of per member still waiting, so the round ends early
Where
Spikefish cast module, PROT entry 0925, tail at 0x801F79B8; round-over test in the battle overlay, PROT entry 0898, at 0x801E67C8
Affects
Every fight flagged as scripted (boss fights), on the USA, Japanese and French discs; only Koru's script can be pushed off its end
Status
Explained - from the code and disc data; the early round end and a boss's thrown-away decision were captured on a poked state in the evolved Cort fight; Koru's own fight was not run

A battle round is a count, not a list of turns. One byte counts how many turns have been taken this round, and the round ends when that count reaches the number of fighters. Who goes next is decided fresh after every action: the fighter holding the highest unspent initiative key.

The flute is an escape item. In a fight flagged as scripted it cannot flee, so only the tail of its code runs, and that tail is meant to throw away the party's remaining turns. It does it by adding one to the turn count for every living party member, subtracting one, and zeroing the party's keys. With p party members already done, the count runs p too far and the round ends p turns early. Only monsters still hold keys, and the highest key always goes first, so the turns that fall off the end belong to the slowest enemies.

So a flute used as the round's first action skips nobody: the rest of the party loses its turns and every enemy still acts. The boss's place in the order does not matter, only how many party members went before the flute. A boss that has already acted has nothing left to lose.

Why Koru never recovers

Koru has no timer. His script picks a move from the battle's round number, and only round number 4 means Dead End Crisis. The round number rises at every round end whoever acted. End that round before he moves and the number is 5, which his script has no entry for; it does not come back to 4 until the byte wraps. The on-screen countdown is 4 - round number stored in one byte, which is why it reads 255. Nothing writes 255 anywhere.

With nothing scripted, the generic monster picker is all that is left. Koru's record carries no usable spell, so it builds a plain attack from his two costed attack animations. Both list their hit at frame 200, on clips only 64 and 30 frames long, so the hit never fires: the animation plays and nothing lands. His real specials take their damage and effect sprites from his own cast module, which a plain attack never runs.

In an ordinary, non-scripted fight the same item ends the battle: the party walks off and the escape teardown runs.

The boss still decides on a turn it never gets

  1. Flute endsparty keys are zero, the count is already too high
  2. Pickthe boss holds the highest key, so it is picked and its script chooses a move · 0x801E5D58, 0x801DAF48
  3. Round-over testthe count has reached the end; the chosen move is discarded · 0x801E67C8
  4. Next roundround number +1, every key rolled again · 0x801E6810, 0x801DA780

For Koru this changes nothing, because his script keeps no memory. For a boss whose script writes something down at the moment it chooses, that note still changes on the discarded turn. Evolved Cort is the clear case: the game records "Ultra Charge was used" when he decides, not when the move plays, and clears it when he decides on Final Crisis. A thrown-away decision can therefore wipe out a charged Final Crisis, or make him fire one next turn without ever visibly charging.

Keys are rolled fresh every round (speed plus a random amount up to half of it), so a fast party's flute user sometimes rolls first, and then the flute skips nobody. That is the "sometimes" in reports about other bosses.

The Japanese and French discs

The trick is not particular to the USA disc. The Japanese build (SCPS_100.59) is a different compile with its overlays loaded higher and some context fields at other offsets, and every link of the chain is there with the same logic. With P seated party members, L alive, M monsters and c turns taken before the flute user: the cursor is c + L after the flute's turn, and the round continues only while it is below P + M - ctx[+0x25].

First-form Cort's key is forced to 30000 by the seeder when the first formation id is 0xB4 and the round counter is 0 (0x801DAAB8..0x801DAAF0).

Verifying it

The Koru half is the part still to be run. Break on 0x801F79F0 and 0x801E67C8. Watch the byte at ctx+0x1A, the byte at ctx+0x28A, the byte at 0x801F6958, and the halfword +0x16C of all four fighters. With the flute used second or third on the round where the counter reads 4, the three party keys drop to zero together, the cursor jumps by (living party - 1), and the counter goes 4 to 5 while Koru's key is still non-zero. Repeat with the flute used first: Koru acts.

For a thrown-away decision, add a write watch on 0x801C8FE4 and a breakpoint on the action dispatch at 0x801E2CDC: the word changes in state 0x50 and no dispatch for the boss follows before the round counter moves.

Open: whether a member who is alive but cannot act (petrified or captured) shifts the overshoot by one, since the flute's loop tests HP only; the two uncaptured rows above (evolved Cort's Ultra Charge direction, Van Saryu); and which of the flagged Rikuroa rows belongs to which of Caruban, the Golem and the Piura.

The War God Icon sometimes gives only one attack string

Reported as
The accessory should make the wearer attack twice in a row, but it randomly fails to; players describe it in solo Muscle Dome Master Course fights (community report).
Cause
The "second pass used" byte doubles as the Low command's AP cost, so typing commands sets it; only an attacker stepping up to a target clears it
Where
Battle action state machine FUN_801E295C and the arts gauge build FUN_801D388C, PROT entry 0898; byte at ctx+0x16
Affects
Every wearer, plain attacks, Arts and counterattacks; in practice one-on-one fights with hand-typed commands
Status
Explained - read from the code, and the refusal captured on a poked state (the wearer was nudged into reach); a refusal with nothing nudged, and how often Noa or Gala hit it, are not measured

There is no dice roll. At the end of the first attack string the game grants the replay only if a one-byte pass counter reads zero.

That byte is shared with something unrelated: the AP cost of the Low command on the arts-entry screen. Every time a fighter's command gauge is built for typing commands by hand, the byte is set to that cost, 30. A doubled attack also leaves it at 2 or more. The game clears it in exactly one place: at the end of the short "step up to the target" phase of an attack.

So the marker reads "second pass already used" at the start of every round whose commands were typed, and stays that way until some attacker, party or monster, has to close the distance to a target. If the wearer swings before anyone has done that and is already within reach, the step-up phase is skipped, nothing has cleared the byte, and the replay is refused. The single pass that does run deals its damage normally.

Fighters are not walked back after an action. A monster that has just hit the wearer is left standing at the very edge of the wearer's reach, and which side of the edge depends on the knock-back of the move it used and on who the wearer is: Vahn's reach is 43 units shorter than Noa's and 96 shorter than Gala's. The failing round is: the wearer is the first to attack, types commands by hand, and targets the monster that hit them last round while it is still within reach. In a crowded fight the other attackers shove the target away and clear the byte, so it almost never lines up. In a one-on-one fight, which is where players report it, it can.

Avoiding it: choose Auto instead of typing commands, attack a different monster, or let anyone else attack first.

Being in reach is not enough on its own: a wearer who starts in reach with a clean byte still doubles. A counterattack by the wearer is decided the same way, since the counterer takes over inside the strike loop and inherits whatever the byte holds. Nothing else cuts the second string: the target cannot die between the passes (the first pass's damage is held back until the second ends), there is no AP check, and monsters never counter.

801d3b3c  sb    v0,3(a2)           ; a2 = s4 + i, i = 0..3: ctx+0x14+i

i = 2, the Low command, is ctx+0x16. Four stores cover the byte and no others: the gauge cost (0x801D3B3C), the clear (0x801E35B4), a per-strike bump that only fires when it is already non-zero (0x801E37BC) and the grant (0x801E3A40). Reading the counter as private to the attack loop misses the first of these. The list comes from a reference sweep of the executable and every overlay that follows the context pointer through both its lui-relative and gp-relative loads.

Battle setup zeroes the byte: FUN_80055B6C clears the whole battle block (0x80055F14..0x80055F24). So in a fight entered with Auto the first attack always doubles, and with typed commands the byte is already 30 before the first swing.

Reach: a party attacker is in reach of a monster when reach_bias[character] + distance < size * 16, with the bias table at 0x80078878 (+43 Vahn, 0 Noa, -53 Gala) and size the monster record's byte +0x1F. The walk chain (states 0x15..0x18) needs an action entry tagged 0x20; six of the 186 monster records have one.

The damage kernel withholds the HP write only while the counter is below 2 (0x801EE114), so a refused pass, whose byte is 2 or more, still applies its damage. The per-strike bump is a one-byte increment: a byte left stale long enough wraps through zero and the next string is granted again.

Verifying it

Watch the byte at ctx+0x16. Break on 0x801E3A18: a non-zero read there is a refused second pass. Break on 0x801E320C with ctx+0x13 < 3 to catch the in-reach bypass, and on 0x801E31FC to log the range result. Writing zero to the byte at 0x801E3A10 restores the double.

The run that would close the remaining gap: a memory-card save with the Icon on Noa or Gala in a one-on-one Muscle Dome fight, commands typed by hand, the wearer faster than the opponent, logging the range result and the string-end read over ten rounds. The prediction is "in reach" and a non-zero read on most rounds that follow the opponent's attack.

Open: a refusal with nothing nudged; how often a Noa or Gala wearer starts in reach; the wearer's own counterattack and the one-byte wrap are read from the code, not captured.

Side Kick's first hit misses floating enemies even with War God Boots

Reported as
War God Boots let Gala's low kick hit floating enemies, but Side Kick still misses its first hit against them (community report).
Cause
Reach is a property of each hit's power byte. The boots swap in a different low-kick record; Side Kick is an art with its own fixed bytes
Where
Melee kernel FUN_801EC3E4, PROT entry 0898, test at 0x801EC488; bytes in Gala's battle file, PROT entry 0865
Affects
One art hit in the whole game; the floating monsters listed below
Status
Explained - from the code and disc data, no capture

Whether a hit can reach a floating enemy is decided by the hit's own power byte, not by anything on the attacker. Low hits come in two encodings: one that cannot reach a floater and one that always connects.

The boots grant no ability. Every pair of shoes ships its own Low and High kick, and the War God Boots' Low kick simply carries the always-connects byte where Gala's other shoes carry the restricted one.

Side Kick is not a shoe's kick. It is an art, stored in Gala's art bank with the fixed power run 12 17. The first byte is the restricted kind, so the first hit misses a floater; the second connects. Changing boots never touches an art record. Across all three characters' art banks it is the only hit encoded this way.

Direction commands play swing records spliced from the equipped items (the footwear section's first record is the Low kick, its second the High kick; the power run is the record's first bytes). Arts play a record from the art bank, selected as record constant - 0x10, power run at +0x24. Side Kick is Gala's action constant 0x23.

Verifying it

Fight an Evil Fly with Gala in War God Boots and break on 0x801EC494. A plain Low reads 0x1D and connects. Side Kick reads 0x12 on its first hit, branches to 0x801EC548 and sets the miss flag; its second reads 0x17 and connects. Changing the art record's first power byte from 0x12 to 0x1C (same multiplier, free range) makes the first hit land.

Open: whether 0x12 is a deliberate low sweep or an authoring slip cannot be told from the data.

The level-3 dance special swallows the next special

Reported as
In the dance minigame, the level-3 special animation "eats" the next special if two level-3 specials are done in a row (community report). The special is the Triangle move, the lesson's "groovy move". An early fan guide gives the same warning: used at level 3, it lasts so long that you miss the next move.
Cause
Presses are only judged while the idle or dance loop plays; the level-3 Triangle move runs 6.83 beats, past the next scoring slot and the next combo's first note
Where
Dance overlay, PROT entry 0980: per-dancer tick FUN_801D1358, gate at 0x801D168C
Affects
Every dancer and every triggered move; worst at level 3
Status
Explained - read from code and data, and captured in the running game with scripted button presses and nothing written to memory

A dancer's button presses are judged only while its body is playing the idle or the basic dance loop. Every triggered move, whether a combo finisher, the Triangle "groovy move" or the flinch after a wrong press, is a one-shot animation, and until it reaches its last frame the judge is not called at all. A press made during it is not stored, not counted as a miss, and for Triangle does not use up one of the three per song. It vanishes.

The level-3 animations are the longest. The level-3 Triangle move lasts 6.83 beats. The next scoring slot closes at most 4.75 beats after the press, so a second Triangle there is always lost. The next level-3 combo starts 6 beats after the press, so its first note is lost too and that combo cannot be completed. A Triangle on the last note of that combo, 8 beats on, does register.

Holding the button does not help: the game only sees a button on the frame it goes down.

The level-3 chart places one three-note combo per eight beats, so two combo finishers in a row never collide. A Triangle dropped inside the lock does not reduce the stock. A Triangle pressed after the lock ends but outside a combo-slot window does spend one, for only a few points, which is the other way a second special can feel swallowed. Triangle pressed together with Square or Circle is judged as Triangle alone, so "with the last command of a combination" means "instead of it".

The code also has a per-dancer "queued move" flag that would start a follow-up move when the current one ends. The move number is written on every completed combo, but the flag itself is only ever written zero: nothing else on the disc that can be loaded with the dance hall refers to it, and a write watch during the runs saw only the two zero stores. The follow-up never fires. It reads as an unfinished "chain the next move" path, which is an inference.

Watched in play

The qualifier (Noa and two rivals) was run in the retail dance hall. Every input went through the emulator's controller; level 3 was reached by pressing the chart's own notes; nothing was written to memory. The run starts from a save state taken on the way into the hall, which then loads the dance code from the retail disc. That state has an unrelated patch resident in the main executable: four code sites differ from the disc, none in the frame-timing or animation code, and the dance overlay's code is byte-identical to the disc's.

The instructions 
801d168c  lw   v0,0x10(s1)         ; idle clip id
801d1690  lh   v1,0x5c(s0)         ; clip bound right now

801d16a0  lw   v0,0x18(s1)         ; dance-loop clip id
801d16ac  bne  v1,v0,0x801d1750    ; anything else: skip the judge
801d16b4  jal  0x801d1af4          ; judge / award routine

The clip driver FUN_800204F8 steps the cursor by (rate * 2 + div - 1) / div times the frame-delta byte at 0x1F800393 and raises the end flag at frames * 16 - 1. Noa's moves all run at rate 8 with divisor 4, a step of 4. The hall runs at a frame delta of 3: the dance init writes the frame-step floor (0x801CF070) and the frame driver FUN_80016B6C applies it, and it read 3 on every play frame. So the cursor moves 12 per game frame and the gate is shut for exactly ceil((frames * 16 - 1) / 12) game frames after the judged one. There is no extra frame for the release: the driver call at the end of the tick that binds the clip is already its first step.

The beat clock advances by the same frame delta times ten, with a beat of 0x119 units, so one beat is 28.1 delta units or 9.37 game frames. A level-2 Triangle reopens the gate 1380 beat-clock units after the press; the next slot's window has closed by 1333.
