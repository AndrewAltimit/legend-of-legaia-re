Turn order, double attacks and kicks

Four oddities players have reported, traced to the game's own code: the Spikefish Flute cancelling enemy turns (the Koru flute glitch), the War God Icon sometimes giving one attack string where two are expected, Side Kick missing floating enemies even with War God Boots, and a level-3 dance special swallowing the next one. Each section says what happens in plain words first, then gives the addresses so other reverse engineers can check it.

How to read this page
Everything here is read from the USA release's executable, its overlays and the data on the disc. Nothing was captured on an emulator. Where a section says what happens in play, that is a prediction from the code, and every section ends with the debugger check that would confirm it. Addresses are for the USA build (SCUS_942.54); ctx means the battle context block, found through the pointer at 0x8007BD24.

The Spikefish Flute cancels enemy turns (the Koru flute glitch)

Reported as
In a boss fight the flute skips the party's remaining turns, and for every party member who already acted it also cancels an enemy turn, slowest enemy first. Against Koru it can stop Dead End Crisis for good (community report).
Cause
The flute's turn-skip adds one to the round's turn count per living party member instead of per member still waiting, so the round ends early
Where
Spikefish cast module, PROT entry 0925, tail at 0x801F79B8; round-over test in the battle overlay, PROT entry 0898, at 0x801E67C8
Affects
Every fight flagged as scripted (boss fights); only Koru's script can be pushed off its end
Status
Explained - from the code and disc data, no capture; the per-boss table is not re-verified

A battle round is a count, not a list of turns. One byte counts how many turns have been taken this round, and the round ends when that count reaches the number of fighters. Who goes next is decided fresh after every action: the fighter holding the highest unspent initiative key.

The flute is an escape item. In a fight flagged as scripted it cannot flee, so only the tail of its code runs, and that tail is meant to throw away the party's remaining turns. It does it by adding one to the turn count for every living party member, subtracting one, and zeroing the party's keys. With p party members already done, the count runs p too far and the round ends p turns early. Only monsters still hold keys, and the highest key always goes first, so the turns that fall off the end belong to the slowest enemies.

So a flute used as the round's first action skips nobody: the rest of the party loses its turns and every enemy still acts. The boss's place in the order does not matter, only how many party members went before the flute. A boss that has already acted has nothing left to lose.

Why Koru never recovers

Koru has no timer. His script picks a move from the battle's round number, and only round number 4 means Dead End Crisis. The round number rises at every round end whoever acted. End that round before he moves and the number is 5, which his script has no entry for; it does not come back to 4 until the byte wraps. The on-screen countdown is 4 - round number stored in one byte, which is why it reads 255. Nothing writes 255 anywhere.

With nothing scripted, the generic monster picker is all that is left. Koru's record carries no usable spell, so it builds a plain attack from his two costed attack animations. Both list their hit at frame 200, on clips only 64 and 30 frames long, so the hit never fires: the animation plays and nothing lands. His real specials take their damage and effect sprites from his own cast module, which a plain attack never runs.

In an ordinary, non-scripted fight the same item ends the battle: the party walks off and the escape teardown runs.

The boss still decides on a turn it never gets

  1. Flute endsparty keys are zero, the count is already too high
  2. Pickthe boss holds the highest key, so it is picked and its AI chooses a move · 0x801E5D58, 0x801DAF48
  3. Round-over testthe count has reached the end; the chosen move is discarded · 0x801E67C8
  4. Next roundround number +1, every key rolled again · 0x801E6810, 0x801DA780

For Koru this changes nothing, because his AI keeps no state. For a boss whose AI writes a flag at the moment it chooses, the flag still changes on the discarded turn. Keys are rolled fresh every round (speed plus a random amount up to half of it), so a fast party's flute user sometimes rolls first, and then the flute skips nobody. That is the "sometimes" in reports about other bosses.

Verifying it

Break on 0x801F79F0 and 0x801E67C8. Watch the byte at ctx+0x1A, the byte at ctx+0x28A, the byte at 0x801F6958, and the halfword +0x16C of all four fighters. With the flute used second or third on the round where the counter reads 4, the three party keys drop to zero together, the cursor jumps by (living party - 1), and the counter goes 4 to 5 while Koru's key is still non-zero. Repeat with the flute used first: Koru acts.

Open: whether a member who is alive but cannot act (petrified or captured) shifts the overshoot by one, since the flute's loop tests HP only. The Japanese release is reported to behave the same; only the USA code is read here.

The War God Icon sometimes gives only one attack string

Reported as
The accessory should make the wearer attack twice in a row, but it randomly fails to (community report).
Cause
The second pass needs a counter to be zero, and that counter is only cleared when an attacker has to step up to its target
Where
Battle action state machine FUN_801E295C, PROT entry 0898; counter at ctx+0x16
Affects
Every wearer, plain attacks, Arts and counterattacks
Status
Partially explained - the failing condition is read from the code; how often play reaches it is not measured

There is no dice roll. At the end of the first attack string the game grants the replay only if a one-byte pass counter reads zero. A doubled attack leaves that counter at 2 or more, and the game clears it in exactly one place: at the end of the short "step up to the target" phase of an attack.

If the wearer's next attack starts already within reach of its target, the step-up phase is skipped. The counter is never cleared, the end-of-string check finds it non-zero, and the replay is refused. The single pass that does run deals its damage normally.

Fighters are not walked back to their starting spots after an action, so being in reach gets more likely as a fight goes on: attacking the monster you are standing beside, or one that has just walked up and hit you. Any attacker who does have to step in clears the counter again, which is why the failure looks random.

Clears itLeaves it
A party attacker who needed the short stepA party attacker already in reach
A monster with no walk animation (uses state 0x19)A monster that walks in (states 0x15..0x18)
Magic, items, Spirit

A counterattack by the wearer is decided the same way. The counterer takes over inside the strike loop, so it inherits whatever the counter holds at that moment: doubled if zero, single if stale.

The instructions

s5 = ctx + 0x11: 5(s5) is the pass counter ctx+0x16, 4(s5) the strike cursor, 2(s5) the acting seat. The grant, at the end of the string:

801e39bc  sltiu v0,v0,3            ; party seat
801e39fc  lw    v0,0x6bc(v0)       ; character record +0xF4
801e3a04  andi  v0,v0,0x2000       ; War God Icon bit
801e3a10  lbu   v0,5(s5)           ; pass counter
801e3a18  bnez  v0,0x801e3a74      ; NON-ZERO: no second pass
801e3a38  sb    zero,4(s5)         ; rewind the strike cursor
801e3a40  sb    v0,5(s5)           ; counter += 1

The one clear, on leaving state 0x19, and the bypass in state 0x14:

801e35b0  sb    v0,7(v1)           ; state = 0x1E
801e35b4  sb    zero,5(s5)         ; pass counter = 0

801e31f4  jal   0x8004e2f0         ; range check
801e3200  bnez  v0,0x801e3230      ; out of reach: approach
801e3210  sb    v0,7(v1)           ; in reach: state = 0x1E, counter untouched

A linear disassembly of the whole overlay finds three stores to the counter and no others: the clear (0x801E35B4), a per-strike bump that only fires when it is already non-zero (0x801E37BC) and the grant (0x801E3A40). The damage kernel withholds the HP write only while the counter is below 2 (0x801EE114), so a refused pass still applies its damage.

Verifying it

Watch the byte at ctx+0x16. Break on 0x801E3A18: a non-zero read there is a refused second pass. Break on 0x801E320C with ctx+0x13 < 3 to catch the in-reach bypass. Predicted reproduction: one wearer alone against one enemy that walks in to attack. The first attack doubles; the next does not, unless a knock-back has put the target out of reach again. Writing zero to the byte before the second attack should restore the double.

Open: how often a party attacker starts in reach in ordinary fights; that battle setup zeroes the counter is inferred, not read; and whether some reports are a second pass that ran but missed.

Side Kick's first hit misses floating enemies even with War God Boots

Reported as
War God Boots let Gala's low kick hit floating enemies, but Side Kick still misses its first hit against them (community report).
Cause
Reach is a property of each hit's power byte. The boots swap in a different low-kick record; Side Kick is an art with its own fixed bytes
Where
Melee kernel FUN_801EC3E4, PROT entry 0898, test at 0x801EC488; bytes in Gala's battle file, PROT entry 0865
Affects
One art hit in the whole game; the floating monsters listed below
Status
Explained - from the code and disc data, no capture

Whether a hit can reach a floating enemy is decided by the hit's own power byte, not by anything on the attacker. Low hits come in two encodings: one that cannot reach a floater and one that always connects.

The boots grant no ability. Every pair of shoes ships its own Low and High kick, and the War God Boots' Low kick simply carries the always-connects byte where Gala's other shoes carry the restricted one.

FootwearLow kickHigh kick
none / Power Shoes / Fighting Boots13 restricted0E restricted
War God Boots1D free18 free
Ra-Seru Thongs13 restricted18 free

Side Kick is not a shoe's kick. It is an art, stored in Gala's art bank with the fixed power run 12 17. The first byte is the restricted kind, so the first hit misses a floater; the second connects. Changing boots never touches an art record. Across all three characters' art banks it is the only hit encoded this way.

The instructions 
801ec488  sltiu v0,a3,3            ; party attacker only
801ec494  lbu   a0,0(a1)           ; this hit's power byte
801ec49c  sltiu a1,a0,0x16         ; 0x16 and up always connects
801ec4c0  lbu   v1,0x1e(v0)        ; target monster record +0x1E
801ec4cc  sltiu v0,a0,0x11         ; class 2: bytes 0x11..0x15 miss
801ec53c  sltiu v0,v0,0x11         ; class 3: bytes below 0x11 miss
801ec554  sb    v0,0x263(v1)       ; miss flag, no roll, no damage

Direction commands play swing records spliced from the equipped items (the footwear section's first record is the Low kick, its second the High kick; the power run is the record's first bytes). Arts play a record from the art bank, selected as record constant - 0x10, power run at +0x24. Side Kick is Gala's action constant 0x23.

Who and what it applies to

Floating monsters (height class 2): Evil Fly, Death Wings, Demon Fly, Drake Ghost, Guardian, Ghost Knight, the Theeder, Vera, Nighto, Viguro, Gola Gola, Slippery, Puera and Gilium families, Pump Bat, Devil Pump, Boogie Pump, Hornet, Killer Bee, Queen Bee, Spikefish, Mad Bird, Wailing Bird, Mage, Sorcerer, Thermo, Amethyst, Garnet, Topaz, the Evil Bat records, Lapis, Rogue and Zora.

Short monsters (class 3, missed by restricted High kicks): Mushroom, Mushrin, Mush Mush, Frog, Gel Frog, King Frog.

Verifying it

Fight an Evil Fly with Gala in War God Boots and break on 0x801EC494. A plain Low reads 0x1D and connects. Open: whether 0x12 is a deliberate low sweep or an authoring slip cannot be told from the data.

The level-3 dance special swallows the next special

Reported as
In the dance minigame, the level-3 special animation "eats" the next special if two are done in a row (community report).
Cause
Presses are only judged while the idle or dance loop plays; the level-3 Triangle move runs 6.83 beats, past the next scoring slot
Where
Dance overlay, PROT entry 0980: per-dancer tick FUN_801D1358, gate at 0x801D168C
Affects
Every dancer and every triggered move; worst at level 3
Status
Partially explained - the lock and its length are read from code and data; which pair of moves the report means is not certain

A dancer's button presses are judged only while its body is playing the idle or the basic dance loop. Every triggered move, whether a combo finisher, the Triangle "groovy move" or the flinch after a wrong press, is a one-shot animation, and until it reaches its last frame the judge is not called at all. A press made during it is not stored, not counted as a miss, and for Triangle does not use up one of the three per song. It vanishes.

The level-3 animations are the longest. The level-3 Triangle move lasts 6.83 beats, while the next scoring slot closes at most 4.75 beats after the press. A second Triangle on that slot is always lost.

Triangle pays its real reward only on a combo slot (every fourth beat) inside the timing window. A press made up to 0.75 beat into one slot can be followed on the next slot no later than 4.75 beats afterwards:

The level-3 chart places one three-note combo per eight beats, so two combo finishers in a row never collide. A Triangle dropped inside the lock does not reduce the stock. A Triangle pressed after the lock ends but outside a combo-slot window does spend one, for only a few points, which is the other way a second special can feel swallowed.

The code also has a per-dancer "queued move" flag that would start a follow-up move when the current one ends. The move number is written on every completed combo, but the flag itself is only ever written zero, so the follow-up never fires. It reads as an unfinished "chain the next move" path, which is an inference.

The instructions 
801d168c  lw   v0,0x10(s1)         ; idle clip id
801d1690  lh   v1,0x5c(s0)         ; clip bound right now
801d1698  beq  v1,v0,0x801d16b4    ; idle: judge
801d16a0  lw   v0,0x18(s1)         ; dance-loop clip id
801d16ac  bne  v1,v0,0x801d1750    ; anything else: skip the judge
801d16b4  jal  0x801d1af4          ; judge / award routine

The clip driver FUN_800204F8 steps the cursor by (rate * 2 + div - 1) / div times the frame-delta byte at 0x1F800393 and raises the end flag at frames * 16 - 1. The beat clock advances by the same frame delta times ten, with a beat of 0x119 units, so one beat is 28.1 delta units at any frame rate. Noa's moves all run at rate 8 with divisor 4, a step of 4. The release is seen one game frame late because the driver runs at the end of the tick and the flag is tested at the start.
