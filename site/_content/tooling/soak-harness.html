Soak harness: random play that hunts softlocks

The route ladders walk a path someone chose and score how far it gets. The soak harness does the opposite: it drives the headless engine with seeded, game-shaped random pad input across every playable scene and every minigame, and reports whatever breaks - a confirm pressed during a door fade, the pause menu opened on the frame a battle starts, a direction held into a picker. Every finding is saved as a j-replay-v1 pad script that reproduces it deterministically, reduced to the input that matters.

The driver

Each run opens a fresh BootSession, seeds the retail New Game party, mounts an empty two-port card rack, seeds the world RNG from the run seed and enters the scene live with the random encounter loop and player-driven battles armed. Then it ticks.

BootSession::tick is not a whole host. Both play hosts do several things around it every frame, and a driver that skipped them would measure its own omissions. The harness does what the hosts do:

Host dutyWhat the harness does
faithful-play armingwhat both hosts set on a bare session: inline field-VM talk, the leading-edge wall footprint, solid NPCs, terrain follow, the NPC ambient walk
presentation queuesdrains the field-event, battle-event, hit, SFX, shout, XA, CLUT-stage and minigame-cue queues after every tick
FMV playbackskips the movie and runs the shared post-play hand-off
name entryroutes the pad edge into name entry and skips the field tick while the overlay is up
shop / prize counteropens a staged shop in a MenuRuntime, steps it on the frame's edges, and unparks the field script when it closes
save screena Save writes into an in-memory card; a Load resumes that block through resume_save

Pseudo-scenes

<venue>+mg<id>
A minigame: the venue is entered, then the same mode-24 door warp the cabinet's op 0x3E makes is armed. The party is given casino coins first - the one non-pad precondition.
<scene>+rt
A save / load round trip on every free-roam frame a player could save on, at a fixed interval: save, resume that file as a Load does, save again - the two must agree field for field. The run starts with one save on the card, so the pause menu's Load row has a file to resume.
<scene>+shop
Every scene with a priced gold shop: the scene's shops are handed to the menu runtime as the merchant's op 0x49 would, since random walking almost never reaches a merchant and picks Buy.
<scene>+talk
Every field scene: the player is stood in front of the next action-button target - NPCs first, then interact-gated props that carry a record - facing it, and the button is pressed. Encounters are disarmed; the run is there for the records.
<label>+rage
Every roster member carries the Evil Medallion's Rage passive for the whole run, so the anim tick delegates the whole party in every battle: the command ring refuses every member, and each round must still open on Begin | Run, reach the commit confirm and play out on the delegated picks.
...@<save>
Any label can lift a library-card save (town01+rt@PRO-14) and play the scene with that save's party, bag and story flags, so late-game scenes are soaked with the party they are reached with.

A talk seat is taken only where play could put the player: on authored walk-visible floor in an open component, somewhere the walk controller's own probes let the player walk a tile away and come back. An actor is faced from 112 units where it can be (a face-on walk stops 104 short of a standing NPC), a prop from 128. The seat is a function of the frame and the world, so a replay takes the same seats.

An @<save> finding is first a question about the entry

A save run still enters its scene by name, not through a door the save's story opens. Three shapes of that are known - Rim Elm's overworld footprint walled in from PRO-04 on, korb3's default seat walled once the arrival cutscene is gated off, and dream's vignettes, which pick their return scene by a flag the sleep leading there sets. They are listed in the harness's SAVE_ENTRY_ARTIFACTS and reported on a "known entry artifact" line rather than in the findings table.

other7 is reported the same way from any run: it is a draft of koin3's MAN that no retail path runs as a field, and its two parks - a 49 0B Incense notice that re-arms itself, a 49 0E past the op's sub-op bound - are retail's own.

Round trips caught a real defect this way: a field save folded actor slots 1 and 2 back into the party records, but in a field those slots belong to the scene, so opurud+rt lost two party records on resume. World::save_party now folds actor mirrors back only in a battle. The library-wide sibling, engine-session/tests/save_roundtrip_library.rs, round-trips every save on the library cards through the card path both hosts take.

Policies

What the policy presses depends on what holds the frame. Every UI surface reads just_pressed, so a press is a tap: the wanted mask on one frame, neutral on the next.

StatePolicy
field / overworldsegments of held walks (straight or diagonal, sometimes with Cross taps), Cross / Circle mashing, a Start tap, idle, and chaos (random masks of everything but Start)
dialogue, or a script holding the playermostly Cross, some directions, some Circle
a script polling the held padthe face button it polls, held - op 0x42 mode 1 reads the held word on one frame of its loop, which a tap hits only by luck
a pickera random number of Down taps, then Cross, once the box's slide has come to rest; the aimed row steps on each time the same picker returns, so a quiz that asks again gets every answer
pause menurandom taps for a random budget, then Circle until it closes
battlemostly the route ladder's fighter (Begin, Attack, Auto, confirm); in the sparring tutorial it follows the lesson, since any other pick rewinds it
minigame / otherrandom face buttons and held directions, rarely Start - the minigames' escape

Detectors

DetectorFires when
panic / tick_errora tick, scene entry or FMV hand-off panics or returns an error
hangone tick runs past the wall-time watchdog; it writes HANG.txt and exits
softlockthe progress digest is unchanged for a whole window while the pad took at least three distinct masks
script_stallthe modal timeline or first helper sits on one PC for a window of field frames - unless its scripted walkers are still stepping, or it is a walk-on record re-polled every tick
battle_loopthree battles open from one parked timeline PC
menu_stuck / battle_endlessthe pause menu survives the Circle back-out; one battle outlasts its threshold
control_starvedthe field refuses the pad with no free-roam frame, the script reaches no new PC, and confirm presses are still arriving
confined900 direction-held frames, all four directions among them, never carry the player 48 units
door_loopsix scene changes inside 600 frames with no direction pressed between them
dropped_to_title / unknown_scenethe mode becomes Title without a game over; a transition names no scene in the set
non_finitea camera float or the caption alpha is NaN or infinite
valueHP / MP over max, live maxima that are not the stat aggregator's rebuild, a level outside 1..=99, a bag stack over 99, a count on a free slot, a duplicated stack
unbounded_growthan engine queue grows past a cap
effect_residuea battle effect is still live on the first field frame after a battle exit or scene load - retail resets the whole pool there (effect VM)
timeline_capthe engine's anti-hang frame cap ended a script context; retail has no such cap, so the record was cut short
save_roundtripin a +rt run, the post-resume save disagrees; the location names the first differing field

The progress digest hashes everything a player could see move: mode, scene, position and heading, every script PC, dialogue, menu, shop and name-entry state, scripted NPC glides, the battle session and every actor's HP, the minigame session, money and bag size. It is deliberately broad: a false "frozen" costs a triage, a false "moving" only a missed finding.

A softlock is located by what holds the frame - pause-menu:<row>:<phase>, battle:state:<action state>, timeline@pc:op, mode:<minigame>, free-roam:immobile@tile(x,z) and so on. A battle park on an absorbing HP-bar pair (the shape that holds the bar-drain gate for good) carries a :hp-bar-absorbing suffix.

  • control_starved catches a script going round. The softlock and stall clocks restart whenever anything moves, so a conversation that reopens its own question passes both forever. Its clock restarts only on free roam, a scene change, or a PC this stretch has not seen.
  • confined is measured, not predicted. It uses the walk controller: the leading-edge probes let a player rest where a flood of the grid says walled, and an actor can shut a seat the grid calls open.
  • door_loop ignores a held direction. A two-way stair sets the player one tile from the door back, so a held direction walks straight back in.

Findings, signatures and reports

A finding's signature is detector|scene|location. Findings are deduplicated by signature and ranked: panics, hangs and tick errors first; softlocks, loops, stuck menus, endless battles, title drops and unknown scenes next; immobility, stalls, starvation and confinement after; value, non-finite, growth and round-trip checks last.

  1. Confirmthe first occurrence is replayed from its pads, truncated to the finding frame, and must fire again
  2. Reducechunks of the pad stream are zeroed while the signature still fires - a bounded delta-debugging pass
  3. Writereplays/<slug>.replay.toml, with scene, seed and signature in header comments TOML ignores

A softlock is reduced under the neutral-pad control, so input that only fed the frozen window drops out; the replay records that in a # soak-min-distinct header. A control_starved finding is reduced only ahead of its window, because a stream cut down to one looping option would starve a healthy conversation too. Every replay names the session configuration it ran under (# soak-arming = "host" or "bare", with a -retail suffix under the hosts' retail mode).

Running

The fixed-budget gate runs a few scenes plus the five minigames and asserts no panic:

cargo test -p legaia-engine-shell --profile release-test --test integration soak_harness::soak_smoke

A long soak is report-only unless LEGAIA_SOAK_STRICT=1:

LEGAIA_SOAK_SEEDS=30 LEGAIA_SOAK_FRAMES=18000 LEGAIA_SOAK_JOBS=8 LEGAIA_SOAK_TAG=big cargo test -p legaia-engine-shell --profile release-test --test integration soak_harness::soak_long -- --nocapture

The headless engine ticks far faster than real time, so a soak is bounded by the minimiser, not by the runs. Overflow and debug-assertion coverage comes from building the same test with those checks on, into its own target directory.

Reproducing and triaging a finding

LEGAIA_SOAK_REPLAY=target/soak/big/replays/<slug>.replay.toml LEGAIA_SOAK_TRACE=60 cargo test -p legaia-engine-shell --profile release-test --test integration soak_harness::soak_replay -- --nocapture

LEGAIA_SOAK_TRACE=N prints a state line every N frames - mode, scene, holder, position, the bytes at every live script PC, scripted glides, and in battle the action state and every actor's HP / display / accumulator - plus each distinct script body once, as hex. LEGAIA_SOAK_TRACE_NPC=<slot> follows one placement; LEGAIA_SOAK_TRACE_WALLS=1 draws the wall bits around the player. The trace goes to the terminal only.

First question: does the input matter at all?

For any softlock or script_stall, run the all-neutral control with LEGAIA_SOAK_MIN_DISTINCT=1.

A fix is checked both ways: the replay must stop firing on the fixed engine, and must still fire on the engine without the fix under the harness as it now stands - a detector that changed since the replay was written can leave it passing for the wrong reason.

Fixtures

scripts/replays/soak/
Reduced replays of open findings, pad input only. soak_fixtures parses each without a disc and, with one, reports whether it still reproduces. It never fails on one that stopped: that is the signal a fix landed, and the fixture moves to fixed/.
scripts/replays/soak/fixed/
Closed findings as regressions. soak_fixed_fixtures fails if a recorded signature fires again; a # soak-expect-max-battles header also bounds the battles a replay may open. Only the recorded signature is asserted.

What it cannot detect

  • Visual or audio wrongness. No frame is rendered and no sample mixed; garbage on screen reads as healthy while the state advances.
  • Retail divergence. Every detector is an internal-consistency check. Wrong damage, a wrong landing tile, a script branch retail does not take - all look like progress. The parity oracles own that question.
  • Anything past the first fatal finding in a run, or past a game over.
  • Deep progression. A plain run starts from a New Game party, which loses most late-game fights; an @<save> run reaches only the states the library card holds.
  • Host drift. A duty a real host performs that the harness does not mirror is invisible here, and one the harness performs that a host has dropped is masked.
