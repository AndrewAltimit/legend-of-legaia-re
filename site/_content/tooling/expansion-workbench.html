Expansion workbench

Build your own maps, story, monsters and game modes for the port, in 3D, in the browser, and share them as one .lxpack file. Everything runs in this tab against your own disc - nothing is uploaded. New to packs? Read what an expansion pack is and the step-by-step guide.

Pack ?

Open the sample pack (the project's example pack, written to learn from), a .lxpack or a pack folder of your own, or start a new pack: empty, from the minimal template (a monster, a fight, a line, a quest and a small map wired together), or as a clone of the sample pack under your own id.

A pack folder is the directory holding pack.toml; the browser reads every file in it.
A pack carries no game data. It names the disc's monsters, scenes, meshes and music by number, and every player supplies their own disc. ?

The names in the pickers (monsters, items, scenes) are read from the disc you load here and shown to you only. A picker writes the coordinate - { kind = "monster", id = 109 } - never the name; a pack holds a name only where you type one.

Every export runs the validator's no-disc-bytes rule. Reference: docs/formats/expansion-pack.md.

Save .lxpack writes the pack as one file, the same bytes every time for the same pack. It is refused while the pack has problems; the checks button says how many and opens them. Your work is also autosaved in this browser.

Play pack installs the pack in the play page's pack library in this browser (replacing the version there), makes it the active pack and opens the play page on it.

Play this map puts you on the map you are building. When a play tab is already open on this pack it reloads the pack in place, with the player where they stood - edit, switch tabs, look. With Live ticked every edit goes there by itself.

Files shows each file of the pack to copy or download one at a time, for a pack kept as a folder.

Find ?

Every place in the pack a value sits. An id (a monster, a line, a quest, a map, a pack flag) lists where it is defined, set, read and referenced; monster:109, item:5, scene:town01 or bgm:12 list a retail coordinate's users; anything else is a text search over keys and values.

Empty, it lists the pack's flags and counters with how often each is set and read: a flag read and never set is a gate that never opens. Click a place to go to the field. Ctrl+K or / focuses the box.

Problems ?

The pack validator, re-run a moment after every edit against the pack exactly as it would be exported, with your disc resolving every coordinate. An error stops the engine loading the pack and stops the download; a warning does not.

Click an issue to go to the field.
