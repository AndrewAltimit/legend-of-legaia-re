Host drift: keeping three hosts on one engine

The port ships one engine behind three framebuffers: the native play window, the browser play page and the browser minigames page. A feature wired into one host and not another is invisible in a diff, because no file holds both columns. This page covers the gates that catch that class of defect, what each cannot see, and the two runs that compare the hosts' actual output.

Both play hosts tick one engine-session::BootSession; the minigames page drives the World-free rules engines directly. Every question below narrows the one before it, and each has its own instrument:

Where the rows live and where the gates run

Tiers 1-3 and 5-17 are scripts/ci/check-ui-host-drift.py (--list prints the surface table, --selftest the detector controls); tier 4 is check-trait-override-symmetry.py. The script is an entry point over a package that keeps the rows a contributor edits (one module per table under rows/), the analysis (one module per tier) and the report apart. A row that names a file no longer on disk would check nothing, so a path check fails the gate on any such row.

  • CI is the authority. Every tier runs in the CI gates job and in the pre-commit hook as a fast mirror. A gate may be hook-only only when its input is gitignored (the Ghidra dump corpus, the extracted disc), and it must then skip cleanly where the input is absent.
  • Nothing above compiles the browser host. The wasm32-only blocks in the web crates are invisible to the host-triple cargo gates, so check-wasm-target.sh type-checks them on a staged change and on every pull-request push.
  • A wasm export is a property of its impl block. A method outside the #[wasm_bindgen] block compiles and passes every gate and is "not a function" in the browser; only a headless run of the built bundle sees that.

The page's own gates, and waivers

  • Sticky renderer state. Every page renderer setter that stores a value until the next call must be staged once a frame ahead of every mode branch, unless classified with a reason. Five such values had been staged in the field branch only, so a battle entered from the overworld kept the overworld's curvature and the field's face cull.
  • Page export reach. Every method the runtime exports must be named by some page source or waived. It is the converse of the tiers, and the only check that finds a feature both hosts lack: the fishing start export was pinned by tests and documented, with no page control calling it.
  • Waivers name a blocking capability - something that does not exist yet, spelled concretely enough to recognise when it lands. "Not wired yet" is undone work, not a waiver. Both waiver files are checked for staleness on every run.

The frame-body trace: same calls, same world?

A source scan cannot see the same calls producing different world state: a step one host runs per redraw and the other per tick, a loop that ends early on one side. The disc-gated host_frame_parity test runs both hosts in one process without a renderer - the native play window's app assembled headless, and the real page runtime driven the way the page's frame loop drives it - samples each display frame (scene, mode, pad edges, world frame, rand() state, script cursor, actors, NPCs, camera, flags, bag, dialogue, battle, menus, audio) and reports the first frame each channel parts on.

Each scenario runs at three cadences - one tick per display frame, two (a 30 Hz display) and one every other frame (120 Hz) - because a clock split between the redraw and the tick is invisible at 60 Hz. Each also asserts what it exercised (a menu opened and closed, a battle was won through to the overworld, each minigame entered and left), so agreement on a world that never moved fails.

The host pair run: same frames?

scripts/ci/host-pair.mjs --site <site> --engine target/release-test/legaia-engine --out <scratch> \
    [--scene town_walk,menu,...] [--mode retail,enhanced] [--every n] [--ticks n] [--from n]

host-pair.mjs runs one scene on one pad script in the play window and in the built play page, pairs them by world frame, and compares both what they hold (the trace text) and what they drew (the share of pixels off at 320×240). It is the one check that sees the page's JavaScript and GL state against the window. --mode enhanced can drop one pass on both hosts (no_ssao, no_lighting, no_fog, no_fade) to split a pixel difference by the pass behind it. Its scenes cover a walk, each pause row, a talk, a shop, an inn, a fight to its results, a summon, every minigame, retail card saves carried from one host to the other, and seeded random presses over the whole pad. A save carries no RNG state, so a card scene seeds one rand() stream on both hosts after the landing (LEGAIA_RNG_SEED natively, debug_seed_rng on the page); unseeded, the two drew different fights.

A healthy pair agrees on every sampled trace and differs by a few tenths of a percent of pixels: hairline pixels on sloped 3D edges where a tie lands on the other side. It prints and asserts nothing; it needs a disc, a built bundle and a display. A scene that is for a screen names it, and its line says VACUOUS when a host never got there: a pause press in the first second of a door entry reaches no accept, and two hosts standing in a field agree on every frame.

Shapes no tier fails on, and open differences

Reading the hosts side by side with every tier green still finds defects, and the shapes recur: one decision fed two inputs (the occlusion-fade arming gate excluded different modes on each host), a rule spelled beside the shared predicate (the page let Start open the pause menu over a shop), an input contract one host does not honour (a held word where the menu wanted edges, so one press stepped several rows), a typed channel narrowed at one host, and opposite defaults on one knob. Four of these shapes became tiers; the rest are decided per instance.

A pump only the field's tick makes is the symmetric form: the cursor auto-repeat is raised by retail's pad pump, which the port ran inside the field tick's set_pad, so under the naming prompt, a shop and the pause menu a held direction stepped once on both hosts while every headless driver saw it repeat. The tick claim now takes the held word (TickClaims::held) and pumps every tick the field does not run, both pause menus cut their edge through BootSession::pause_menu_edge, and three trace scenarios hold a direction on each screen at 30, 60 and 120 Hz.

Some differences are deliberate and listed as such: the two default key layouts (a desktop layout and WASD walking cannot share one table), the output level (the site's pages share a quieter level), the in-frame settings panel only a window needs, and the platform-only features: the touch pad, quality step-down, VR and a card port swapped mid-session on the page, netplay hosting and the pack folder watch in the window. One is open work: the window's pixel-exact scaling, which the page's fixed, layout-stretched canvas has no twin for.

Where each shared decision lives

The full page keeps one row per decision that has one engine implementation both hosts call - the frame loop and its clocks, cameras, lighting, screen effects, menus, saves, audio routing - and most rows are pinned by a tier-3 row on the kernel's name. A host that re-spells one locally is drift.

  • Gaps absent from both hosts fail no tier, because a symmetric absence is parity. The ones found that way - the overworld curvature, the field drop shadow, the battle ground shadow, the scene-entry fade - now draw on both hosts through one kernel each.
  • The field readout over the battle transition: retail draws none, because the transition overlay loads into the slot the HUD lives in; one suppress kernel carries that term for both hosts (the party readout).
  • Settings and saves share their kernels too. The launcher’s and the window’s first settings row and the page’s Look and feel selector answer through one preset (legaia_engine_session::look_and_feel): Enhanced, Original (Retail-faithful plus PSX rasterisation) or Custom, over the same rows. A card or .lgsf either host writes loads on the other with the port’s own words intact - the run rules, a pack’s progress block and dance free play’s song counter - and the page keeps its card and sessions in localStorage.
  • Adding coverage is mostly declaring: a screen appears on the surface by existing, a paired constant or feature joins by its row, a diagnostic by being declared, a boot install by being an engine call both boots make, and a situation by a scenario in the frame-body trace that fails when the run never reached it.
