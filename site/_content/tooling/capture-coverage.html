Capture coverage: which parts of the game the retail corpus has seen

The retail comparison corpus scores the engine at every captured moment, and its headline is only as broad as the moments it holds: a median score over states that all stand in a handful of scenes, fighting a handful of monsters, says nothing about the rest of the game. This report takes its denominator from the disc, the way disc coverage does for code, asks of every scene, monster, attack, cast and screen whether some retail state shows it, and ranks what to capture next.

At a glance

scripts/ci/capture-coverage.py                # build, census, report under captures/capture-coverage/
scripts/ci/capture-coverage.py --no-build     # reuse target/release-test/legaia-engine
scripts/ci/capture-coverage.py --census F     # report from an existing census JSON
scripts/ci/capture-coverage.py --summary      # the headline table only

The census itself is legaia-engine retail-compare --census <json>. Like the corpus driver, the script exits cleanly with a [skip] line when the save library or the extracted disc is missing.

What counts as covered

Two tiers per item. Held: some corpus state made on a retail disc shows it (a state that replays a patched executable never covers anything). Scored: that state also carries an image score in the corpus baseline. A held item that is not scored is a capture the corpus cannot yet seed, or one whose frame is a fade.

DimensionDenominatorA state covers an item when

Battle screensthe command flow's surfaces and the results windowa battle state stands on it
  • An action counts only while it is on screen: the action state sits in the attack chain, the magic or item flow, the summon flow or the module sequence. A prompt or the clean-up after the hit covers the monsters but no attack.
  • A boss's scripted cast names an id its record does not carry, so the census is its only witness: a seen scripted cast joins the denominator as its own item. The record-carried items are fixed by the disc.
  • Which module a cast pages follows the two loader paths of the cast module page: the summon band by id, a capture-class record by its own index.

Ranking the worklist

  • Monsters and enemy attacks by how many formation rows across all scenes hold the monster, with the scenes it is met in - the places to walk to capture it. A monster no row holds is a scripted fight.
  • Enemy magic attacks by how many monster records carry the id.
  • Cast modules by how many spells share the module.
  • Scenes towns first, then fields, then the overworlds.

The report closes with every held item and the states that hold it.

Filling the worklist

Every new state is made by playing the retail game under PCSX-Redux, pad only where possible, and every poke a probe does make is recorded with the state.

ProbeWhat it captures
autorun_battle_harvest.luaWalks from a field state until an encounter, plays rounds with Spirit so the monsters act, and saves a state whenever a monster's action is mid-way. LEGAIA_WANT names a formation by its monster ids and lets retail's own encounter roll pick it; knobs keep a low-level party alive, wound the monsters so a heal has a patient, or keep the pre-pick state for the cast-sequence oracle.
plan_walk_route.py + autorun_walk_route.luaA planned walk for scenes a random walk never reaches: the planner searches each scene's collision grid with the teleports as edges and writes a route; the probe walks it on the pad, fights what it meets, and saves a state in every scene it enters. ACT and TALK lines work cabinets, counters and the conversations a route must have.
autorun_door_hop.luaCrosses a chain of doors by holding the player on each door's walk-on tile; the door's own record runs with its story gates, so a closed door ends the run.
autorun_screen_walk.luaA list of waits, presses and saves gated on the game mode or the sub-screen word, for screens behind a conversation or a menu path, such as a shop's lists.
  • A one-swing monster sits in the strike loop for a single pass: the loop stages its last byte and leaves together (battle action), so the default hold of 8 vsyncs never sees it and the attack stays uncovered however often it swings. LEGAIA_HOLD=1 saves it on the pass after the band opens. The sparring tutorial refuses Spirit, so its fight wants LEGAIA_SPIRIT_ROUNDS=0.
  • LEGAIA_WANT keeps each region's tile box, so a scene whose live condition group covers only tiles the walk never reaches rolls nothing. LEGAIA_WANT_WIDE=1 widens every box to the whole map, and the state's description says so. A source state whose player carries the movement-disabled bit (an event holds it) takes no step, so no roll fires either way.
  • Party strikes are the thinnest dimension and where a harvest finds the most new reading. LEGAIA_PARTY_ARTS lists per seat the arts to enter as direction tokens, cycled over the rounds; the probe takes Attack, enters the art, commits, and captures each seat's strike loop at LEGAIA_PARTY_HOLDS vsyncs in. LEGAIA_MONSTER_TOUGH=1 restores the monsters at each prompt so a fight outlasts the list, and LEGAIA_PARTY_TRACE=1 writes a per-vsync trace of the attack chain (state, cursor, committed and staged clip, close-up accumulator, yaw). The states register as battle_<scene>_party_<char>_<art>_{open,mid,late}.
  • A planned walk only attacks, so a story fight runs one battle-flow cycle a round for as long as it lasts; a long two-foe fight that cycles every couple of thousand vsyncs reads like a battle that restarts, but it is one fight. An ACT line's shot window does not fight at all.
  • A scene change need not be a door. The inn-night variant of a town is loaded by the innkeeper from the Yes of the stay picker, so asset scene-nav lists it under the NPC's record with no door slot, and a route reaches it with a TALK line.

A state is a valid run of the game whichever way it was reached, so state-making runs take run_probe.sh --fast --turbo: no display, several at once, well above 1x (headless runs).

A harvested state is a candidate until its census row shows the seat, category and id its label claims, its retail frame shows that attacker (and the spell's name banner, for a cast), and it is backed up with its scenario block naming the source state, the probe, the vsync and any poke it inherits. The scores of that scratch run are what it adds to the corpus at the next reviewed baseline update.
