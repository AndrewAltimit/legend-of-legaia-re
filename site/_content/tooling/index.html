Tooling

Two kinds of tools live here. The first are for you: point them at your own Legend of Legaia disc and they extract every asset, re-roll the game from a seed, or translate its text. The rest are the project's reverse-engineering instruments - the Ghidra, emulator-capture and measurement tools the format docs and engine port are built with. Pick a task below and follow the card.

Pick a task

Every tool takes a disc image you supply (the project ships no game data); most read the extracted/ tree the extraction pipeline produces. The groups are in arrival order: get the assets off the disc, then either patch the game or dig into how it works.

  • Extract assets - turn the disc into PNGs, meshes and audio; the starting point for everything else.
  • Patch a disc - randomizer, ROM patcher, language packs. Shipped deliverables, not side effects.
  • Dig in Ghidra - the static path: disassemble the executable, recover the RAM overlays, answer "who calls this?".
  • Capture the emulator - the dynamic path: watch the retail game run and record what the code actually does.
  • Measure the port - how much of the game is understood, how much is ported, and whether the port matches retail.
  • Beyond Legaia - how reimplementation compares with decomp and recomp, how its fidelity is measured, and what carries to other PS1 games.
  • More tooling docs - CI gates and triage ledgers, on GitHub only.

Extract assets

Almost everything on the disc lives inside one archive, PROT.DAT, as containers within containers. One command unpacks the whole chain.

./legaia-extract "/path/to/Legend of Legaia (USA).bin" --out extracted

Dig in Ghidra

The static path. Ghidra runs headlessly in Docker, driven by scripts; every FUN_80xxxxxx on this site is a function it labelled. One fact shapes all four pages: most of Legaia's game logic lives in overlays - code the game pages into RAM on demand - not in the executable, so "no static caller" is a question, not an answer.

Measure the port

How much of the game is understood and reimplemented (port catalog, disc coverage), how much of one entry's bytes a parser really consumes (byte accounting), whether the port matches retail (the retail comparison corpus against save states, the differential oracle frame by frame), whether it matches itself run twice (determinism), whether it plays from New Game to the credits (the full-game ladder), and what breaks when nobody plays it sensibly (the soak harness).

Beyond Legaia

Legend of Legaia has been ported twice over the same months: a static recompilation, which translates the executable and models the hardware, and this project, a new engine in Rust written from the format docs and the traced disassembly. The case study puts them side by side, with decompilation as the third route: what each gets up front, what it has to earn, and why reimplementation is more practical than it used to be. A recomp gets you the game. A reimplementation, plus the oracles that measure it, gets you an engine for the game.

What it gets you
No PS1 machine model underneath, so the game draws through a wgpu renderer, builds to WebAssembly for the browser, runs in VR, and takes enhancements such as lighting, fog and SSAO with the retail-faithful mode one toggle away (fidelity and enhancements). Modding works by game concept: an expansion pack is TOML naming monsters, maps and quests, and patcher features proved against retail graduate into engine toggles. And the rules are readable: each one is a named Rust kernel carrying the retail address it was read from.
How fidelity is kept
Measured, not inherited, since nothing of the original runs. The retail comparison corpus scores the engine against several hundred retail save states; the cast-sequence oracle films a cast on both sides frame by frame; the audio sweep and real retail PCM score the sound; the retail kernel differential runs a retail routine off your disc beside its Rust port; the full-game ladder plays New Game to credits on pad input. Every score is a ratchet that may only rise.
What it costs
Fidelity is a long tail, paid continuously: each divergence has to be found, read and fixed, and what the corpus has not seen is unmeasured. The work rests on decompilation-grade analysis of the disassembly, routine by routine; it does not replace it. And the measuring instruments are a project of their own.

The pages below make the case at length and hand over what carries. The disc reader, the Sony-format parsers, the GTE and SPU models and the emulator save-state readers describe the PlayStation, not this game, and the measurement method serves any route: a decompilation or a recomp can use the same oracles as a regression check.

Disc-gated tests

Tests that touch a real .bin run only when LEGAIA_DISC_BIN is set; without it they skip and pass, which is how CI runs. Source builds put the binaries under target/release/.

LEGAIA_DISC_BIN="/path/to/Legend of Legaia (USA).bin" cargo test --workspace
