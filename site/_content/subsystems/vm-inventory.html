VM inventory

A census of every VM-shaped subsystem in the retail runtime - anything that walks a bytecode or record stream through a dispatcher, or advances a per-entity state byte through a switch each frame - with three independent facts for each: how completely it is decoded, whether the Rust port implements it, and whether a live caller in the port reaches it.

Three facts to keep apart

  • “Five VMs” is an orientation, not a census. Five bytecode-and-state drivers share the actor model. The 0x2F extension, the 0x4C sub-dispatcher and the battle-action, world-map and tile-board state machines are separate dispatchers with their own tables.
  • “Ported” is not “live”. Port status and reachability are separate columns. A faithful, tested module that nothing outside its crate calls is inert.
  • Whether the disc uses an op is a third fact. A ported, live handler can still have no carrier - no shipped scene issuing that opcode. For the field VM a disc-wide opcode census answers it per arm, and its zeros separate “no fixture drives this” from “there is nothing to drive”.

Every row has a live caller in the port. The battle-action state machine is the one row whose decode is graded partial: its table is sparse and not every band is mapped.

The cast band is 64 dispatchers and one row

Each of the 64 slot-B images carries its own phase machine over the same context byte, so the “cast-module phase machine” is not one interpreter - it is a family that shares an ABI. The battle-action state machine re-enters the paged module’s tick every frame and advances only on a zero return. See cast modules.

The effect VM has no opcode space

A low opcode count is not evidence of an incomplete decode, and here the count is zero by construction. FUN_801E0088 has no central switch on a per-slot opcode byte: the bytes that look like state tokens are 5.3 fixed-point wait counters, and the walker is a pair of countdown-driven cursor walks. Searching for its opcode table is a documented dead end.

Ported but inert

“Inert” is a reachability statement, not a correctness one. Two support modules stay inert today: the title sprite-emit primitives, and a standalone walker over the 0x2F dispatcher. The second is owed no host - a disc-wide reference scan finds exactly one caller of that dispatcher, and the port hosts that caller.
