Boot path

Everything between the disc spinning up and the moment you press NEW GAME. The publisher logos fade by, the wordmark appears - and behind that the game reads its archive directory, streams its first code overlay and enters the “what mode am I in” state machine that runs for the rest of the session. This page follows that chain, the title screen, and the scripted opening NEW GAME starts. The per-address tables live on boot internals.

The boot chain

A cold boot is six writes of a literal into the mode word. Each one hands the frame to the next screen, and none of the screens is named in the mode table - which is why the order has to be read off the stores rather than the table's dev labels.

  1. Hardware initGPU, CD, sound, heap; the PROT.DAT directory and the CDNAME name map into RAM
  2. Mode 16 · READ INITone frame: upload the four init.pak logo textures
  3. Mode 17 · READthe publisher logos fade in, hold and fade out
  4. Mode 22 · CARD INITstream PROT 0899 into slot A
  5. Mode 23 · CARDthe title screen, ticking as a spawned actor
  6. Mode 2 · MAIN INITNEW GAME: stream the field overlay 0897, load opdeene
  7. Mode 3 · MAINthe field loop - the game proper

Almost every PlayStation game bundles its files into one archive so the disc can stream them; Legaia’s is PROT.DAT, with a table of contents saying “entry N starts at sector S”. Reading that table is job one. Job two is the asset-type dispatcher: each asset’s size word carries a type byte, and one router hands the bytes to the matching handler (asset-type). Job three is the mode machine below.

The main loop

After hardware init, main() spins forever: run the current mode’s handler; if the handler wrote a different mode, tidy up and switch. A mode’s INIT handler runs for one frame and usually streams an overlay into slot A; its per-frame handler runs the game from then on, through the master frame driver that ticks actors, VMs and draws. Writing the mode word is the only way to change what the game is doing.

Most gameplay code is not in the executable. The field VM, dialog renderer and battle logic live in overlays streamed into slot A. “Zero callers in SCUS_942.54” never means dead code - it means the caller is in an overlay. Init stages in order: internals.

The game modes

Walking a town, fighting, browsing the pause menu, watching a movie - to the game these are modes, and exactly one is active. Half the table is dev tooling the retail disc never enters; these are the ones a player sees:

  • The mode word does not say which minigame. All five share modes 24/25; the sub-id the door warp wrote (op0 − 100) picks the overlay (warp flow).
  • The dev names mislead. CONFIG is the debug menu, READ is the logo screen, CARD is the title and the whole menu. The full 14-row table, with every INIT handler address and the dev modes, is on internals.

The title screen

The title screen is a small program of its own: an attract countdown that eventually plays the opening movie, a Press-Start wait, a two-row NEW GAME / CONTINUE menu, the memory-card manager, and the launch. It runs as a spawned actor under the CARD pair, whose INIT loads PROT 0899 - which is also why the title shares code with the save screen. The tick (FUN_801DD35C) is a 25-way sub-mode switch.

  • Attract. A countdown starting at 0x8000 drains each frame; when it underflows the game switches to movie mode and plays MV1.STR (cutscene), then comes back to the title.
  • NEW GAME fades out, writes mode 2 and the scene id opdeene. CONTINUE detours through the card-load path first and then writes the same mode 2.
  • No arrow cursor. The two menu rows are a band of the title sheet; the selection is shown bright vs dim.

State struct, countdown instruction and the packed pad-mask layout the tick reads: internals.

Where the title overlay lives on disc

The title code is the tail of PROT entry 0899 - the same entry whose head is the options-menu bundle - streamed raw and uncompressed straight into the overlay window: 74 sectors from LBA 47227, in five DMA bursts that all land inside the entry. The same tail carries two embedded TIMs, the save-menu UI atlas and the memory-card icon strip. Sector ranges and burst offsets: internals.

What NEW GAME launches

Press NEW GAME and you do not get a name-entry screen. You get a scripted opening - the creation-myth crawl, the Seru intro, the Mist story, a fly-in over Rim Elm - and only once you stand in Rim Elm does “Select your name” appear. Every leg is an ordinary field scene chained by its own script, not a movie.

  • The fresh-state seed. Gold is set to a hard-coded 500, a story-flag region is zeroed, and the executable’s starting-party template is expanded into the live 0x414-byte character records, default names included.
  • The intro skip. Once opdeene’s timeline raises a scratchpad flag bit, a confirm press fades out, sets the town01 entry coordinates and issues a name-based scene change to town01. The target name is a literal in the field overlay, which is why opdeene’s own data holds no town01 string.
  • Name entry opens from town01’s opening timeline (field-VM op 0x49 sub-op 3): a 6×17 letter grid plus a Backspace / Space / End row, and a Yes/No commit. The name lands in the character record at +0x2A7.

Skip conditions, the scene-change packet and the name-entry grid’s addresses: internals.

Boot-time art

Three separate sources feed the boot screens.

  • Publisher logos - PROT 0895 init.pak. Four uncompressed TIMs (PROKION, Contrail, “SCEA Presents”, an epilepsy warning) played by the bundle’s own sequencer in the order SCEA, Contrail, PROKION. The fade is not alpha: the quads are opaque and the sequencer scales their vertex colour, so the PSX texture blend texel × colour / 128 darkens them to black. The warning is uploaded and never drawn - its sprite descriptor is the one no emit call passes.
  • Title wordmark - PROT 0890. One 256×256 sheet holds the orb, wordmark, Press Start prompt, copyright lines and the NEW GAME / CONTINUE footer; retail samples it in bands, and a demo-build label on the sheet is never drawn.
  • System-UI textures - in no entry at all. A 118-sector gap between the TOC and the first indexed entry holds the menu font, the boot cursor and several sprite sheets.

Per-logo offsets, quad rectangles and pacing; the wordmark's source rectangles; the gap's seven TIMs: internals. The play page and the native window both run the logo stage ahead of the title card.

Debug flags

Two RAM values decide whether the game behaves like the shipped disc or a dev station. On real hardware both read “retail”; a cheat device can flip them, which is how the debug menu on the retail disc becomes reachable.

AddressRoleRetail value
_DAT_8007B8C2dev / retail loader selector, read as a halfword at 40 sites; != 0 takes the PROT-index path, == 0 opens a host path that ends in break 0x1031, written once by main()
_DAT_8007B98Cdebug-mode word tested by the input dispatcher and ~14 field-overlay gates; poking its top byte _DAT_8007B98F to 1 makes every gate read active, and SELECT+△ opens the debug menu0
History: why both flags were once read backwards

A sweep for absolute lui+offset references saw no writer for the loader flag, because the one write is gp-relative, and concluded it booted at 0; the executable’s header carries b_size = 0, so no BSS is cleared either. The debug byte returned zero byte-granular references because consumers read the word. Both are under do-not-re-walk; the gp-relative blind spot is why the address reference scan checks all five forms.
