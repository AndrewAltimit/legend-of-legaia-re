Chapter-1 hub sweep

Every overworld leg reachable from Drake Kingdom's map01 in chapter 1: which tile enters which scene, which record in the scene's MAN (its script-and-data bundle) carries the entrance, and which story flags gate it. The entrance model itself is on the world-map page; this page is the per-leg table that validates it.

At a glance

Scope
map01's interior legs beyond the story spine (town01 → map01 → keikoku, map01 → rikuroa / dolk → dolk2): cave01, vell, vozz, suimon, jou, and the four-deep Drake Castle interior.
Method
Decode each leg from disc bytes, then drive it in the engine: walk town01 → map01, step on the portal tile, confirm the scene loads with its MAN present.
Notation
P1[n] / P2[n] = MAN partition-1 (placements) / partition-2 (trigger records); [a,b,c] = record counts per partition; C1 blocks if any flag is set, C2 requires all.
Result
No C1/C2 progression gate stands between a fresh Drake arrival and any of the five hub legs. The gated doors are inside them.

The Drake Castle interior

  1. jouCastle grounds, MAN [15, 8, 7]; the door P2[5] sits behind 0x44D.
  2. jouinaNot terminal: exits to jou and jouinb, both ungated; busy-latch C1 = [0xF].
  3. jouinbMAN [19, 7, 13], fully ungated: P2[9] back, P2[10] deeper.
  4. jouincMAN [43, 18, 60]; lists jouinb and jouind; most P2 records are door-choreography records behind the 0x00F busy mutex.
  5. jouindPer-visit door band on flags 0x4BE..0x4C2; the next room, jouine, exits only through a movie.

Once the 0x44D door is passed the deep castle is open, and the engine walks jou → jouina → jouinb → jouinc in one session. The door-record families are described on the script VM page.

Decoder pitfalls

  • Frame shift. CDNAME block numbers are raw TOC indices; the extraction frame is raw - 2. An unshifted window bleeds two entries into the next scene's block - which is how dolk2 once appeared to share a MAN with suimon. In the retail frame suimon keeps its 2345-byte [10,7,3] MAN and dolk2 resolves its own streaming carrier. Position law: scene-v12-table.
  • Partition asymmetry. A partition-1 destination scan under-reports doors carried only by P2 records (jouinb's return door); a P2 walker or the strict portal-site join sees them.
