How the game works

What Legend of Legaia is doing under the hood: what loads when you walk through a door, how a battle turn resolves, why the world-map ocean shimmers, how a cutscene plays. Each page here covers one piece of the engine - what it does in the game, where its code lives, and how it hands off to the next piece. The map below shows how the pieces connect; click any box to open its page. Start with Boot path if you're new, or Engine reimplementation if you're here for the Rust port.

The map

Almost all of the game happens in the field - walking a town, talking to people, opening doors. Everything else is a place the field hands you off to and gets you back from: a battle, the world map, a movie, a minigame, a menu. Under all of it sit three services that every mode uses: the asset loader, the renderer and the sound stack.

Where the code lives

The game shipped without symbols, so a routine's RAM address is its name: FUN_8002735C is one specific traced function in the project's dumps. Half the runtime lives in the main executable SCUS_942.54 and is always in memory: boot, disc reads, the asset router, two of the bytecode VMs, the audio and rendering libraries. The other half is overlays - chunks of code streamed off the disc into one shared RAM window when a mode starts. Only one of them is resident at a time, which is why the world map, save, shop and level-up screens are parts of the field, menu and battle overlays rather than overlays of their own.

Script engines

Most in-game behaviour is authored as data - scripts the designers could change without recompiling - and run by a handful of small interpreters. Four are clean opcode dispatchers; the effect VM is a per-slot state machine with the same role. The VM inventory lists every interpreter-shaped subsystem, including the ones too small for a page of their own.

Menus and town services

Everything that happens in a window. Almost all of it lives in the menu overlay; the inn is the exception.

Pause menu
Items, Magic, Equip, Status, Options: the 52-record window table every screen is built from, and what each screen draws.
Inventory
One 256-slot bag reached only through five helpers bounded by an active window - the “split bag” that shrinks to 128 slots for a lone character.
Save screen
Port pick, card check, block grid, write: the save block is a straight copy of live RAM with an additive checksum.
Shop
Stock inline in the town's script, prices from one item table, selling pays half, and a hidden strip of stock for Platinum Card holders.
Inn
No inn system at all: each inn is a scripted conversation and the price is a number typed into it.
