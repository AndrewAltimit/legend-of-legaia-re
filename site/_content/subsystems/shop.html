Shop

Talk to a merchant, pick Buy or Sell, choose an item and a quantity, confirm, and the gold moves. The surprise is where the data lives: a merchant’s stock list is not a table anywhere on the disc - it sits inline in the town’s own event script - while every price comes from one item table in the main executable. Only the screens are shared code, hosted by the same menu overlay that draws the pause and save screens.

Where the stock comes from

The MAN is each scene’s script-and-data bundle. Inside it, a merchant is one field-VM instruction carrying a count, a run of item ids and the vendor’s name. The count over-counts: it includes a trailing run of unsellable, price-0 placeholder ids that the on-screen shop skips. The price table therefore doubles as a sellable mask: a record must lead with a priced item, and the unpriced tail is trimmed. Every shop on the disc partitions cleanly this way.

TrapRule that avoids it
Requiring every id to be sellablerejects nearly every shop - most records carry the placeholder tail. Trim, do not reject.
Walking opcodes linearlydesyncs on a dialogue picker’s jump table and silently misses shops (Biron Monastery). Byte-scan for the op signature instead.
Trusting the CDNAME labela #define name N names extraction entry N − 2; resolve the scene through block_for_extraction_index.

Read a town’s stock off a disc with asset shop-stock --prot PROT.DAT --scus SCUS_942.54 --cdname CDNAME.TXT --scene bylon; it prints “decodes 10 ids, sells 7” rather than truncating. The casino prize counter is a different system: its table lives in the menu overlay and debits the coin bank, not gold.

Prices, purses and the Point Card

  • Buy price is the item table halfword; there is no per-shop price anywhere.
  • Sell price is exactly half the buy price. A zero-priced item shows “Cannot sell”.
  • Stack cap 99. A row greys once the held count reaches 99, and the quantity picker clamps to 99 − held.
  • Point Card (item 0xFE) is a third purse, passive while held. Each purchase credits price / 20 per unit - 5% - before the gold debit; sales never accrue. A one-line toast (window 31) shows the balance after each buy.
  • Buying equipment first asks who it is for: a party row checks the equip mask and, on a match, equips immediately and returns the replaced piece to the bag.
Details: what spends the Point Card

The bank’s only debit is a battle effect arm: entry 14 of the effect jump table takes min(bank, 9999), subtracts it from the bank and applies it as damage to the target - the Point Card strike. No item descriptor on the disc selects arm 14; the battle-action caller passes the actor’s +0x1E8 byte as the selector. The card’s descriptor carries flag bit 0x40, shared only with the summon flutes; its meaning is unpinned.

Screens and row ink

Each shop window is a record in the menu overlay’s window-descriptor table (field menu); the 9-slice frame is caller-drawn and each renderer only paints content from its window origin. Text indents 20 px, lines are 14 px apart.

Row ink is last-rule-wins. Three tests run in order and each overwrites the last: a full stack greys the row; the record’s “owned / restricted” marker re-inks it to the accent pen even so; an unaffordable price greys it again even so. On the mode panel, an empty bag dims Sell - and Quit with it, because nothing restores the ink between the two draws.

Details: cursor word bits and the window choreography

The picker cursor word (DAT_801E46BC): low 12 bits = selected row; bit 0x1000 = blink phase; bit 0x2000 = parked presentation (every row drawn, keyed to blink); bit 0x4000 = cursor suppressed. The stock list re-runs the same decode against _DAT_8007BB98; shared kernel engine-core::shop::shop_cursor_mode.

Opening and closing slide the windows through widget scripts: the open script (DAT_801E4E38) brings in vendor name 0x21, mode panel 0x2A, gold 0x20, 0x28 and 0x22; the Sell transition (DAT_801E4E54) slides away 0x28 / 0x2A / 0x22 and keeps the gold and name plates. The randomizer’s Seru-trading vendor patches exactly these seams to grow the panel to four rows.

Every equipment bonus record on the disc carries the 0x40 no-passive sentinel, so the sell panel’s passive lines always come from the item-effect table arm.

History: the casino list filed as the shop list

The 8-row, 14 px layout of FUN_801D5DE0 was once filed as the shop buy list on the strength of its dump filename, overlay_shop_save.bin. That name identifies the image the routine came from, which carries casino code too; the routine itself never reads the gold purse. The shop’s real buy-list row layout is untraced.
