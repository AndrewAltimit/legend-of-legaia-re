Netplay

Multiplayer for the port: one player hosts a world and others join it - for a card table, a golf round, prop hunt, or roaming a shared map. Retail has no networking at all (it reads only pad port 0), so everything here is the port's own: a versioned wire protocol, two session cores, the transports and the legaia-relay server in crates/netplay, joined to a running game by crates/engine-netplay. How to play: playing online.

At a glance

The netplay crate names no engine crate. A session drives anything that implements one of two small traits, so a game-mode session from engine-modes and a whole World plug in the same way, and the protocol and session cores do no I/O, which keeps them buildable for the browser host.

Simulation contract
lockstep::Simulation (tick(&[u16]), state_hash()) or authority::EventSim (apply_event, state_hash).
Models
Lockstep (every peer simulates from every seat's pad) and host-authoritative (the host simulates; the others send actions).
Transports
In-memory loopback with simulated latency / jitter / loss, native raw TCP and WebSocket, browser WebSocket (feature web, wasm32 only).
Server
The legaia-relay binary, or the same server in-process via RelayServer::spawn(addr).
Access control
Room codes only - LAN and friends use (security posture).
Dependencies
None beyond the workspace's clap (CLI) and the web-sys family (browser); the WebSocket handshake's SHA-1 and base64 are in-crate.

The layers

The relay's RelayCore is the whole relay as a state machine with no sockets; RelayServer runs it on threads, and LocalRelay runs it over any transports from the caller's loop (the test harness, or a same-machine room with no sockets).

Wire format

One relay port serves two stream framings, told apart by the first four bytes a client sends:

First bytesFraming
LGNPRaw TCP: then u32 LE length + message bytes, both directions.
GET WebSocket (RFC 6455): the opening handshake, then one binary frame per message. Client frames are masked, server frames are not; text frames and extensions are refused.
anything elseThe connection is closed. A GET that is not an upgrade gets 400 and is closed.

A message is a one-byte tag followed by its fields. Frame numbers, ids and lengths are LEB128 varints; hashes are fixed 8-byte little-endian; pad words are 2-byte little-endian. Every variable-length field has a cap, checked before anything is allocated, and a whole message is at most 16 KiB. Trailing bytes after a message are an error. The protocol version is negotiated once, in Hello: a relay refuses a client of another version, so no later message repeats it.

Rooms and the lobby

The first message on a connection is Hello. To create a room it names a seat count (1 to 8); the relay picks a six-character code from a 32-symbol alphabet without the look-alikes 0/O and 1/I, makes the sender host and seats them at seat 0. To join it names a code; the relay admits the client only if the room is still in its lobby, has room, and the client's engine build id and pack identity (pack id plus SHA-256 of its bundle) equal the host's byte for byte - two different builds or packs would run different rules and diverge on the first frame that touches them. A joiner takes the lowest free seat, or spectates when the seats are full; the host can move anyone with AssignSeat.

Start is the host's alone, and only once every seated member other than the host is ready. The relay replaces the start order's seat map with the lobby's (seat index to player, empty seats to the AI) and sends it to the whole room, host included, so every peer starts from the same order. A started room admits no one.

EndSession, from any member of a started room, returns it to the lobby: the relay clears everyone's readiness, sends the notice (stamped with the sender) and the lobby, and admits joiners again. The lobby is not idle time: shared-world roaming runs there, so the relay carries guests' Actions to the host and the host's Snapshots to the room in the lobby as well as in a host-authoritative session.

When the host leaves the lobby, the earliest-joined remaining member becomes host (HostChanged). During a lockstep session the same migration happens; the host has no simulation privilege there. A host-authoritative session ends instead (RoomClosed(HostLeft)): the state lives on the host and nobody else holds it. An empty room is freed at once.

Refusals that only concern the request (no such room, room full, wrong build or pack, not ready, not host) leave the connection open so the client can try again; a protocol-version mismatch, a malformed frame, the connection or room cap, and the rate limits close it.

Lockstep

Every peer runs the same deterministic simulation from every seat's pad word, frame by frame. LockstepSession<S: Simulation> is the core:

  • Input delay. A peer samples its pad for frame f + input_delay while simulating frame f, and sends it. Frames 0..input_delay run on zero pads everywhere, so nobody waits at the start. The delay hides that much one-way latency through the relay; beyond it the slowest link sets the pace.
  • Stall. Frame f is simulated only once every human seat's word for f is known; until then advance() returns Stalled with the seats being waited on. wants_local_input() stops the local pad running more than the delay ahead.
  • Redundancy. Every input packet repeats the sender's last K words (default 8, at most 32). After a few consecutive stalled calls the latest packet is sent again, so a lost packet is covered even when the stall itself stops new packets. The relay transports are reliable streams; the redundancy serves an unreliable input channel and is exercised by the loopback link's input loss.
  • Checkpoints. Every checkpoint_interval frames each peer hashes its state after the tick and sends the hash. A hash that differs from a peer's for the same frame is a desync, reported once with the frame, both hashes and the peer's seat; by default the session then halts. Spectators verify but send nothing.
  • Pause. pause() stops the local pad and tells the room; every peer stops sampling, and the simulations stop within the input delay, all on frames fixed by the inputs already sent. resume() clears it.
  • Dropped players. When a seated player disconnects, the relay re-sends that seat's last packet and announces SeatController { seat, Ai, from_frame } with the end of the last input frame it forwarded. No peer can have simulated from_frame without an input that never comes, so every peer switches the seat to the AI at the same frame (Simulation::set_seat_controller).

What a simulation owes

state_hash() must be equal for equal states on every platform: no pointer values, no HashMap iteration order, no floating point a target can round differently. tick() must depend on nothing but the state and the pad words - no wall clock, no host RNG. It is the contract the replay harness already holds World::tick to. A World-backed simulation additionally has to give each seat's word somewhere to go - retail reads only pad port 0 - which is the hosts' multi-avatar work, not this crate's.

Rollback

Rollback - predict missing inputs, simulate ahead, restore a snapshot and re-simulate on a misprediction - needs a snapshot cheap enough to take every frame. The mode sessions could provide one; a whole World cannot (it is large and holds scene resources), which is why the core is delay-based. Input packets already carry frame numbers, so rollback would add a RollbackSimulation trait (snapshot / restore) and leave the wire format unchanged.

Host-authoritative

One player owns the state; the rest send intentions and follow. It suits what is turn-based or what only the host can resolve.

  • Turn-based events (cards, poker). A client sends Action; the relay carries it to the host stamped with the sender. AuthorityHost turns it into an event through a host-supplied validator (which can refuse it, for example out of turn), applies it, and broadcasts Event with a sequence number and the post-event hash. AuthorityReplica applies events in sequence order, buffering early ones, and checks each hash. A replica whose simulation can serialise itself (EventSim::save_state / load_state) recovers from a mismatch, or from joining late, by asking for a StateBlob and holding events until it arrives.
  • Shared-world roaming. The host broadcasts every avatar's scene, position, facing and animation frame as a Snapshot at 10 to 20 Hz. AvatarInterpolator keeps an estimate of the host's frame clock and draws each avatar two snapshot intervals in the past, between the two snapshots that bracket that moment: positions interpolate linearly, facing the short way round the 4096-unit circle, and a scene change snaps. Past the newest snapshot it holds the last pose rather than extrapolating, so a stalled link freezes an avatar instead of walking it through a wall.

Host a world

  • Standalone: legaia-relay --bind 0.0.0.0:7462 (the default port), for a dedicated machine on a LAN or a small server.
  • In-process: the hosting game calls RelayServer::spawn(addr) and gets a RelayHandle with the bound address; it then connects to 127.0.0.1:<port> like any other client, creates the room and shows the room code and its address. Dropping the handle (or shutdown()) closes every room, tells each client RoomClosed(ServerShutdown), and joins every thread; nothing is left listening.

Native clients connect with StreamTransport::connect_tcp or connect_ws; the browser host connects with WebSocketTransport::connect("ws://host:port/"). A page served over https:// may only open wss:// sockets (loopback excepted), and the relay does not do TLS itself, so a relay reached from the published site sits behind a TLS-terminating reverse proxy that forwards the WebSocket upgrade.

Security posture

The relay is for LAN and friends. Its only access control is the room code, and it never touches the file system or the game: it speaks the netplay protocol and nothing else, refuses every HTTP request that is not a WebSocket upgrade, and holds no game data.

Per room the relay keeps only the lobby rows, the seat map and, per seat, one frame counter and the last input packet - no frame history - so a room's memory is bounded by the caps above whatever a session's length.

Play with people you trust

There is no authentication beyond the code, no encryption (use the TLS proxy) and no cheat prevention. The relay stamps every input, checkpoint, chat line and action with the sender's real seat and id, so a peer cannot speak for another, but a lockstep peer chooses its own seat's inputs freely and a host-authoritative host decides everything.

In the hosts

engine-netplay joins the protocol to a running World. Both play hosts drive one room::NetPlay per player, once per tick, before the world's tick: it pumps the transport, runs the room screen when it is open (the pad goes to the screen, not the world), and drives whichever phase the room is in.

Modes

The host picks an instance from the world's mode list (the active pack's, or the built-in practice set) and starts it; every peer builds that instance from the start order's id and seed. The first room seats fill the mode's seats; a mode seat with no player is the AI, and a player whose room seat the mode lacks roams instead. Golf seats the whole room. The session runs in the world's own mode seat (PackModeSeat::networked), so it draws through the offline screens, with "You" on each player's own seat; it grants nothing.

KindModelWhy
Golf, racing, prop huntLockstepReal-time; only pad words and checkpoint hashes travel.
Poker, Grid DuelHost-authoritative view streamTurn-based; poker hides hole cards.

Lockstep. ModeSim is the Simulation: the real session lives in the world's seat and is swapped into the lockstep core around each advance, so the screens draw the simulated state. A desync ends the game for everyone with the frame and seat on the room screen; a dropped player's seat goes to the AI on the same frame everywhere.

View stream. Only the host runs the session. A guest sends its pad word when it changes; the host feeds one change per tick to that seat, so a press and its release arriving together still give the session a pressed frame. After a tick that changed what a guest sees, the host sends it a numbered StateBlob: the table as that seat may see it plus the tick's log lines worded for it. A guest's own copy of the instance is built from another seed and only labels the screen. Under the view stream a poker guest never receives another seat's hole cards before the showdown, and then only the live hands; Grid Duel is played with open hands and passes through unredacted. The price is a round trip of input latency, which a turn-based table does not notice, and that the session ends if its host leaves (diagram on expansion game modes).

Leaving a mode (the quit prompt, or the results screen) sends EndSession; another player still mid-game is returned to the lobby with a notice, while one reading the results keeps them until they leave.

Roaming

Players roam their own worlds. A guest reports its avatar (scene id - the scene's first PROT entry -, position, facing, idle or walk clip and frame) to the host at 15 Hz; the host broadcasts all of them, its own included, as one snapshot; every peer draws the others in its scene through the AvatarInterpolator. Outside the field (a menu, a battle, a mode) an avatar is reported with no scene and drawn nowhere.

The limits, by design: nothing but avatars is shared. Each world runs its own scripts, encounters, doors, dialogue and battles, so two players see each other walk but not each other's fights or story state; there is no collision between avatars. A remote player is drawn as the local party leader (posed with the local leader's clips at the reported frame), since a field scene loads only its own leader's rig. Emotes are chat lines (* Vahn waves), not animations. Prop hunt runs on the mode's own arena and pad movement, not on a field map.

Tests

crates/netplay/tests/ is disc-free, all of it:

  • codec_roundtrip.rs - every message variant round-trips, every strict prefix of an encoding is refused, random bytes never panic the decoder.
  • lockstep_loopback.rs - 2, 3 and 4 peers through the relay core over links with latency, jitter (so reordering) and 5% input loss agree on the state after 10 000 frames of a toy simulation; a diverging peer is caught by everyone at the next checkpoint; a dropped seat goes to the AI on the same frame everywhere; pause and resume.
  • relay_lobby.rs - admission checks, seats and spectators, readiness, host migration, sender stamping, rate limits and caps.
  • authority_rooms.rs - replicas follow the host through validated turn-based events, a stale replica recovers from a state blob, snapshots reach the others, the room closes when its host leaves.
  • socket_smoke.rs - the threaded relay on an ephemeral 127.0.0.1 port with one raw-TCP and one WebSocket client playing lockstep; every wait has a deadline and the port is checked closed after shutdown.

crates/engine-netplay/tests/ (disc-free) runs whole Worlds, each with its own NetPlay, through the relay core on loopback links:

  • modes.rs - two poker hands over the view stream, the guest never holding the host's hole cards before a showdown; a golf round and a prop hunt match in lockstep with every shared frame's hash equal and one result; a desync caught on both peers, both back in the lobby and able to start again; a racer who leaves handing the seat to the AI while the rest race on.
  • roaming.rs - a guest walking moves its avatar on the host, trailing it and never backwards; chat and emotes reach the room.
  • sockets.rs - a host and a guest on the threaded relay over real TCP on an ephemeral port play poker frames; the port is closed after shutdown.
