Audio

How Legaia makes sound. The town theme that starts when you step through a gate, the clang of a sword hit, the shout a character gives when an art lands - each takes a different road from the disc to the PS1's sound chip. Music is a MIDI-like score played through a sampled instrument bank; effects are one-shot samples keyed on a voice; voices and cutscene audio are streamed straight off the CD. This page follows all three roads through Sony's statically-linked sound libraries, and shows how the clean-room engine rebuilds the stack.

How it works

The PSX has a dedicated sound chip (the SPU, Sound Processing Unit) with its own 512 KB of memory. Games can't talk to the SPU directly from main RAM - they use Sony's PsyQ libraries (libsnd for sequencer playback, libspu for low-level voice control) which speak the SPU's wire protocol. Legaia links both statically, so the libraries are part of the game binary and can be inspected like any other code. That inspection is how this page was written: the FUN_80xxxxxx names throughout are RAM addresses of functions in the Ghidra trace.

PSX games typically split audio into three concerns: sound effects (short one-shot samples), BGM / music (sequence-driven - a SEQ is a MIDI-like note stream played through a VAB instrument bank), and streaming audio (XA - compressed audio the drive plays straight off the disc). Legaia is no exception, but its plumbing is layered:

  • A path-string cluster at 0x8007B380 holds the file extensions the sound subsystem appends to scene-asset paths: .spk, .LZS, .dpk, .MAP, .PCH, .pac, STR, plus the master file bse.dat.
  • Two loaders in SCUS_942.54 turn those paths into actual reads: a sound-init / .dpk loader and a streaming-asset loader for XA-family files and banks.
  • Underneath sits Sony's PsyQ SsAPI sequencer (libsnd) for SEQ playback, plus the libspu primitives that move bytes into SPU RAM.

BGM dispatch is the surprising part: there is no "BGM ID → file" table anywhere. A scene's own script writes a track id, and a per-frame poller turns that id into a PROT.DAT entry number by arithmetic over the disc layout. "The table" is the archive itself.

Finding the sound files

Before anything can play, the bytes have to come off the disc. Retail reads them by PROT.DAT entry number; a dev-station path (h:\...) survives in the same functions but is never taken on a retail disc.

Sound banks

An instrument bank (VAB) is a set of sampled sounds plus the tuning and envelope data that turns them into instruments. Legaia keeps a handful of them resident at once - a system bank, the current music's bank, the field bank, two monster banks in battle - each parked in a numbered SPU slot.

VAB format

Sony's standard VABp-magic instrument bank, documented at formats/vab. The dominant on-disc carrier is the scene-VAB-prefixed streaming shape - the VAB body is preceded by a 4-byte chunk0 header. Multi-bank archives sit at 0889_sound_data2, 0890_sound_data2, 0891_level_up; the vab_01 cluster is the standard distributed-bank layout. Implementation: crates/vab (header parser + extractor + ADPCM decoder).

VAB slots - one installer, twelve records

Every bank retail opens goes through one installer, and its argument is the same category byte the SFX descriptors carry. FUN_8001FC00(raw_toc_index, category, buf, append, len) streams the entry into a staging buffer; FUN_8001E54C(category, buf, len) then walks the streamed chunk list and installs it, taking the header buffer from the 12-byte mixer record at 0x80091508 + category*12 and the VAB slot from that record's +8, and opening the bank through FUN_8002630C → SsVabOpenHead (at the SPU address the per-slot table at 0x800917B0 holds) → SsVabTransBody.

Monster sound bank - monster.snd

Every enemy's roars and hit sounds live in one packed file. The loader is FUN_8003E104(monster_idx, slot, dst_buf) - called twice from the battle scene loader FUN_800520F0 (slots 7 and 8, for the active battle's two monster banks). It reads the file's per-monster TOC at 0x801C8980 - 0x10 (4-byte stride, paired entries giving [start_lba, end_lba+1]), computes the LBA range, and dispatches on _DAT_8007B8C2: the dev path (== 0) uses the host-trap file API on h:\mpack\monster.snd; the retail path stages (size, dst) into the gp window at +0x97c / +0x894, kicks the async CD read via FUN_8003F128, and sets a 120-frame timeout at +0x91c.

Hero victory voices. The same file's TOC (count word 0xCE at +4) has tail clips carrying the party's victory-pose voice lines, streamed by the same loader at results time - which is why those vocals survive any sweep of the XA/ files. The results sequencer FUN_8004E568 picks a pose tier from the actor's HP (≥ 3/4 max → tier 0, ≥ 1/2 → 1, ≥ 1/4 → 2, below → 3; a status in mask 0x107B forces tier 4), a pose action id (0x11..=0x18) from the per-character table at SCUS 0x800788A0, and a clip byte at 0x80078867 + action + char_id*8 fed to FUN_8003E104(clip, 7, dst). Per-character clip bands: Vahn 0xB8..=0xBC, Gala 0xBD..=0xC3, Noa 0xC4..=0xCB.

Sound effects

A footstep, a menu blip, a sword clang: each is a one-shot sample keyed on an SPU voice. The game describes every effect with an 8-byte record - which program in which bank, how many voices, how loud - and the actor or script that wants the sound just names the record.

Per-actor SFX trigger

Looks up a sound entry at &DAT_8006F198 + sound_id*8 for sound_id < 0x200, or in the runtime-allocated table at _DAT_8007B8D0 for higher IDs (the .dpk consumer's bank). The static table is 100 descriptors (ids 0x00..=0x63); the < 0x200 check is a bound, not the size. Each entry decodes as [+0 program][+1 tone/region base][+2 note-level][+3 voice-count + sustained bit 0x20][+4 category]; the helper calls FUN_800653C8 (libspu SpuKeyOn-equivalent) for each of voice..voice+count-1. Move-VM and field-VM opcodes write actor[+0xac] (sound ID) and actor[+0xb0] (voice); the move-VM tick re-fires the SFX whenever the trigger flag at actor[+0xb4] is set. The cue-ring drainer FUN_80016B6C reads the same table and programs each voice via FUN_80065034.

Engine SFX bank + scheduler

SfxBank::from_descriptors builds the catalog from the disc-decoded static table. The bank those programs index is named by the cue itself: FUN_80065034 calls FUN_80068B98(vab_id, program) before the program lookup, repointing the libsnd current-bank globals at the VAB slot the descriptor's +4 category selects. The engine therefore stages the two pinned SFX banks itself and fires each cue with SfxBank::play_one_shot(spu, vab) against the one its category names, falling back to the scene VabBank only when nothing is staged. SfxScheduler queues each request with its retail timing offset and dispatches when the per-frame tick reaches the firing frame - a HitCue::timing_frames = 1 cue plays one frame after the strike begins. Implementation: crates/engine-audio/src/sfx.rs.

History: "a cue plays out of the scene's music VAB"

An older reading held that the libsnd current-bank globals simply hold whichever bank is open, so a cue would play out of the scene's music VAB. That was a save-state artefact: the globals are shared with the sequencer, so a state sampled after a BGM note holds the music bank. The program-change call inside FUN_80065034 is what actually selects the bank per cue.

Music: which track plays, and how it starts

Walk into Rim Elm and the town theme starts; walk into a fight and the battle theme takes over. Nothing in the executable maps a place to a tune. The scene's own script says "play track 2016", and a per-frame poller turns that number into a disc entry and hands it to the sequencer.

Resolver arithmetic

The field VM's opcode 0x35 writes the BGM ID to _DAT_8007BAC8. FUN_800243F0 (the per-frame asset poller) reads it and branches on slti … 0x7d0:

BranchResolved PROT indexGlobals
bgm_id < 2000 (scene-local)*(0x80084540) + 6 + bgm_id0x80084540 = scene block base
bgm_id ≥ 2000 (global pool)*(0x8007BC64) + (bgm_id - 2000)0x8007BC64 = music_01 bank base

The result is stored to 0x8007BAB8 and compared against the currently-loaded index at 0x8007BA9C, so re-selecting the playing track is a no-op. On a running retail image 0x8007BC64 holds 990 - the raw in-RAM TOC pool base. Extraction-frame indices run two below raw (the +2 filename skew, see cdname), so the bank's low range sits at extraction 988. See script VM for the resolver code.

The music_01 bank is piecewise

Every real music track on the disc lives in the music_01 bank - scenes carry no SEQ of their own. A global-pool id is 2000 + slot and equals the debug sound-test track number; each bank entry is one self-contained [VAB][SEQ] pair (chunk header, pBAV body, then a pQES score). The bank is piecewise in extraction space: 988 + i for index i ≤ 67, 990 + i for i ≥ 68, with a 2-entry gap at 1056/1057. music_labels::prot_entry_for_bgm_id owns that map; a flat base gets the top of the sound test wrong. Playing a track means uploading that entry's own VAB into SPU RAM and driving the sequencer against it, not the scene VAB the field path stages. The site's minigame pages take exactly this path (render_music01_bgm): Baka Fighter loads extraction 1043 (#55), the dance overlay 1048/1054 (#60/#66); the slot machine, fishing and Muscle Dome start no track and inherit their host scene's BGM.

Which track a scene plays

The track is script-selected, not table-driven. The scene's own event script picks it with an op-0x35 operand, so the resolution is recovered by running the scene's prescript and observing the emitted id (crates/engine-shell/tests/bgm_scene_resolution.rs does this across the CDNAME corpus). The law that sweep establishes: every scene that starts BGM selects a global-pool id. The scene-local branch is never taken by a field scene, and a scene's own scene_vab_stream-wrapped SEQ is not its music source - fingerprinting a playing track against the scene-local corpus fails for this reason. The sweep sees a scene's entry track only: cutscenes change music with sub-op 9 from timeline records the sweep never reaches, so "which track does scene X play" can have more than one answer.

The track-swap handshake

A cutscene can choose the exact beat the outgoing score dies on. FUN_800243F0 runs a stage counter at gp+0x744 through a 7-entry jump table (0x800108C8), entered only while a track change is in flight: wait for CD idle and arm a 30-frame settle delay; tear down and close the BGM slot unless sound-flag bit 0 is set; kick the async load; count the delay down; install the SEQ (FUN_8001E54C); re-attach the slot unless bit 1 (pause) is set; latch. The sound flag word _DAT_8007B750 coordinates it with the script:

BitMeaningSet byCleared by
0script-owned start pending (defer slot teardown to the script)sub-op 9poller commit, scene entry
1BGM slot paused / detachedsub-op 2, sub-op 3, dance overlaysub-op 1, 4, 0xA, scene entry, game-over
2script flag (opaque to the sound side)sub-op 6field overlay

4release-ack - script has released the old slot occupantsub-op 0xApoller commit

After setting bit 3 the poller stalls while bit 0 is set and bit 4 is not: a swap started by sub-op 9 keeps the old track until the script commits with sub-op 0xA, which waits for bit 3, releases the paused occupant, sets bit 4 and clears bit 1. A port that honours the sub-op 2 pause but drops the 0xA commit leaves the music paused after the cutscene. Engine side: BGM bytes resolve synchronously, so bit 3 is satisfied on arrival and SceneHost::route_bgm_events routes sub-op 0xA straight to BgmDirector::unhalt_pause. Provenance: ghidra/scripts/funcs/800243f0.txt, 800266e0.txt, 80026520.txt.

Entry-script pauses. A scene's entry script can start its track and immediately pause it for a story moment - town01 starts global id 2016 then, while system flag 0x225 is clear, issues a sub-op 2 pause (the opening's silent dawn, repaired by the opening cutscene's own sub-op 9 restarts). A scene-picker entry runs that script with none of the choreography behind it, so the engine's free-roam staging (World::seed_free_roam_story_baseline) drops a sub-op 2 issued inside the scene-entry window on picker entries only; the new-game chain keeps the authored pause.

Battle ↔ field music swap (engine)

The port reuses the same dispatch: World::set_battle_bgm configures a battle track id, the live loop queues an ordinary FieldEvent::Bgm{sub_op: 1} start on encounter (swap_to_battle_bgm) and resumes the stashed field track on battle end (restore_field_bgm), both through AudioBgmDirector::start_inner. The shipped default is global id 2026 (retail's battle_id == 0 bundle = extraction 877 = sound-test #26). Retail BGM changes are hard cuts (or short SsSeqSetVol ramps), so start_inner swaps the faithful way: AudioOut::swap_bgm key-offs the outgoing sequencer (its notes release through their own ADSR envelopes) and installs the new one to tick from its first event that same instant, with only a couple of frames of click-guard fade-in on the master. The older serial cross-fade (crossfade_to) held the incoming intro near-silent for half a second and is no longer used for BGM transitions.

Battle voices: shouts and the melee grunt

When Vahn lands a Somersault he shouts. That shout is not an SPU sample - it is a short CD-XA clip streamed off the disc, picked at random from a small per-art pool so it doesn't repeat back to back. The plain melee swing works the same way, which is why a port that only wires up the SPU stays silent in a fight.

Retail: the staged-animation materialiser (FUN_8004AD80) calls the cue selector FUN_8004C140(char_id, action_constant, flag), which picks a channel from the art's candidate pool and fires the CD-XA clip player FUN_8003D53C(clip_slot, channel, dur). Clip files are per character: Vahn = XA2.XA, Noa = XA4.XA, Gala = XA6.XA (16-channel short-mono banks). The SCUS cue tables are parsed by legaia_art::arts_voice, capture-verified via PCSX-Redux call-site traces and recomp-runtime rounds (arts_voice::CAPTURED_ART_CHANNELS). A second trigger exists: the animation cue track (FUN_800508DC) can fire a shout mid-clip. The ordinary melee swing is two emissions from FUN_801EC3E4: the XA30 grunt via FUN_8003D53C(0x1D, chan, dur), and cue 0x10C through the router FUN_8004FE5C, which takes the XA voice leg for a party attacker.

Engine: executing arts pushes one BattleShoutCue per art performed (apply_battle_art); boot demuxes XA2/XA4/XA6 from the raw 2352-byte sectors (read_arts_shout_bank, disc-image boots only); AudioBgmDirector::play_art_shout resolves the pool pick (// PORT: FUN_8004C140) and AudioOut::play_xa_shout mixes the PCM in the way the PSX CD input does - never through the 24 voices. Two timing behaviours model the CD contract: a ~150 ms response delay (the shout trails the animation start) and back-to-back requests queue rather than cut. The melee grunt and the 0x10C impact cue are not yet staged (no XA30 bank at boot, and the live battle loop emits no cue for plain swings) - see battle-action for the cue census.

Sony's sequencer: SsAPI / libsnd (0x80061-0x80067 cluster)

The music player is Sony's, not Legaia's. It walks the SEQ bytes, keeps per-channel state, and turns note events into SPU voice key-ons - the same libsnd every PsyQ game shipped, which is what lets its functions be named. The cluster lives in SCUS at 0x80061B18..0x800681D8 and uses the standard SsAPI globals: a 16-slot allocation bitmap, per-slot 0xB0-byte sequence-state structs, and two Legaia-installed function-pointer hooks (_DAT_801CE564/_574) that wire the script VM's seq context in. Engine port: the clean-room SPU

crates/engine-audio ports the SPU side of the stack as a clean-room model. No Sony bytes; the spec is this page plus the libspu API surface and the public PSX SPU register layout.

Reverb: Studio C, always on

Every room in Legaia has the same faint hall echo - because retail sets one reverb configuration at boot and never touches it again. The retail SPU implements reverb as a same-side / different-side IIR reflection pair feeding a 4-tap comb and two all-pass stages, run at 22050 Hz over a work buffer at the top of SPU RAM. The port reproduces that network register-for-register in spu::reverb, loading the standard libspu preset (public hardware-reference constants, not game data) into a recirculating i16 work buffer; the multiply is signed Q15, so a 0x8000 coefficient inverts phase exactly as the hardware does.

  • Master-enabled in every captured state (SPUCNT bit 7) - field, town, battle, summon, title, minigames.
  • The mode is Studio C everywhere - the 32 reverb registers are byte-identical across every captured state and match the StudioC preset exactly (dAPF1=0x00E3, work area 0x6FE0).
  • Per-voice reverb-send is broad - typically 15-22 of 24 voices, BGM and SFX alike. Reverb is the default routing, not a per-cue effect.

The live engine matches this by calling Spu::set_retail_reverb() once at SPU init. Pinned by a sweep of the save-state corpus (mednafen-state spu). A "Spirit-Arts / echo cues selectively opt into reverb" reading is falsified by that sweep, and the SEQ controller census finds no CC91 (reverb depth) events. Approximations: the hardware's 39-tap FIR resampler is decimation + zero-order hold, and output volume uses a fixed depth (Reverb::set_output_volume).

Engine port: the sequencer

legaia-engine-audio::Sequencer is the runtime side of the SsAPI cluster. Its surface mirrors SsSeqOpen / SsSeqPlay / SsSeqClose / SsSeqSetVol without copying any Sony bytes:

Sequencer::set_loop_to(idx)External loop-point fallback for tracks with no in-stream markers.

Voice allocation is round-robin over the 24 SPU voices, tracking (channel, key) → voice so the matching key-off shuts the right slot. Tempo events override the running tempo at the event's absolute tick. Pitch bend (0xEn) sets the channel's 14-bit wheel and re-pitches sounding voices; the bend range is a per-tone disc value (pbmin/pbmax). Loop points come from the stream: controller 99 value 20 = Loop Start, value 30 = Loop Forever; end-of-track after a Loop Start rewinds to the marker, and the rewind resets the integer sample clock so every pass re-fires on the same offset. Controller census across every SEQ-bearing PROT entry: CC7 and CC10 carry the bulk, CC99 only the loop markers, CC11 and CC91 are absent.

Timebase. The production path ticks the sequencer once per SPU sample, so the music clock is locked to the audio clock, with an exact integer accumulator - no per-tick float, no drift, bit-deterministic for the replay oracle. The SEQ tempo gotcha: the header tempo is a 240 BPM placeholder, immediately overridden by the first body 0xFF 0x51, which in PSX SEQ carries its 3 tempo bytes with no MIDI length prefix. Mis-parsing that override pins playback ~3× too fast. See formats/seq.

XA-ADPCM Confirmed

Cutscene audio and voice clips are streamed CD-XA - the drive plays them directly, interleaved with video sectors, without the CPU or SPU voices in the loop. crates/xa decodes CD-XA 4-bit ADPCM bit-exactly: on a real cutscene track its per-channel PCM matches an external lossless reference decode sample-for-sample. The on-disc .XA / .STR audio is standard CD-XA Mode 2 Form 2. The demuxer (legaia_xa::demux) splits raw 2352-byte sectors by (file_no, ch_no) - the subheader carries the channel number, which a 2048-byte ISO view strips - and the group decoder reconstructs each channel.

History: the "non-standard interleave" reading

An earlier reading had ~90% of XA sound groups failing validation and inferred a bespoke interleave. That was Form-1 truncation damage in the old extractor, not the format. See do-not-re-walk.

Audio-trace parity oracle

How do we know the port's sound matches? By comparing which SPU voices are active, frame by frame, against a real PS1 emulator running the retail disc. This is the audio sibling of the VRAM and mode-trace oracles.

The retail side has two capture shapes, both emitting the same AudioTraceFrame JSONL wire format:

  1. Single-cycle snapshot lifted from a mednafen save state's SPU section via legaia_mednafen::PsxSpu (24 voice records, master volume, voice-on/-off masks, reverb mode, SPU RAM). One save → one retail frame. Convergence: "did any engine frame in the window match retail's voice mask?".
  2. Multi-frame trace captured by autorun_audio_trace.lua inside PCSX-Redux: per-vsync PCSX.createSaveState() calls, the SPU sub-message sliced out via FFI, decoded offline by extract_audio_trace_from_sstates.py. Convergence becomes "for every retail vsync with audio playing, did the engine ever match?" (first_audio_trace_divergence_multi).

The engine side runs a standalone Spu + Sequencer alongside a headless BootSession::tick, driving BGM through a private TraceBgmDirector that routes op-0x35 events in lock-step with SceneHost::route_bgm_events - so the engine trace does play music. Convergence rule per retail frame: at least one engine frame's active_voice_mask is a superset of retail's AND every retail-active voice matches start_addr. NoFrameMatched is tolerable drift (the prescript may not emit op 0x35 inside the window); VoiceStartAddrMismatch and MasterVolumeMismatch are hard failures. PCSX-Redux's Lua API does not expose the SPU register file directly, so the probe writes only the ~600 KiB SPU sub-message per vsync; Channel.Data.on || .stop is the audibility criterion (ADSRInfoEx.state reads Sustain even for unused voices).

  • Library: engine_shell::audio_trace_oracle - build_engine_audio_trace, load_runtime_audio_trace_from_save, load_runtime_audio_trace_jsonl, first_audio_trace_divergence[_multi].
  • CLI: legaia-engine audio-trace --scene NAME, --scenario LABEL (single snapshot), or --retail-jsonl PATH (multi-frame).
  • Disc-gated tests: audio_trace.rs auto-discovers scenarios with a save; audio_trace_multi.rs needs LEGAIA_AUDIO_TRACE_JSONL_DIR.

What's left

The per-scene .dpk / sound_data2 pack is decoded as a VAB + SEQ bundle (type-0 VAB header + type-1 samples reconstitute one VAB; type-2 = SEQ), parsed by legaia_asset::sound_pack. The bse.dat master bank's header word and record stride are pinned (the +2 ushort is an even byte-offset splitting it into two sections); what its record columns mean is still unknown. The .MAP / .PCH PsyQ SoundArtist intermediates are dev-side inputs that produce these VABs, not separate on-disc retail chunks. On the engine side, the melee grunt / impact cue path (an XA30 bank and cue emission from the live battle loop) is the audible gap.
