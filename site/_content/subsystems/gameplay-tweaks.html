Gameplay tweaks: patcher features in the engine

The disc patcher proves a change against the original game, on a console or an emulator. A change that is a fix or a gameplay option rather than new disc content is expected to graduate into an engine switch, so a player of the port gets it without patching a disc. This page sorts every patcher feature into one of three classes and lists the switches the engine carries.

Two ways a patcher feature reaches the engine

The engine reads its game data from whatever disc it is given, and it never executes the game’s MIPS code. That splits the patcher in two.

  • Data edits reach the engine on their own. A randomized drop table, a re-priced shop, a rescaled monster record or a re-routed door is bytes the engine parses at boot or scene entry.
  • Code hooks do not. The engine runs its own Rust ports of the routines a hook patches, so a hook’s behaviour exists in the port only when the port implements it.

Every patcher feature falls in exactly one class. Class (b) is either carried (a switch below) or open (ranked at the end).

A launcher or page slider cycles a fixed step list that starts at retail; the flags take any value in range. The two fixes default on because a game the defect never touched plays identically with them: the Fortress fix changes nothing on a save without the stale flag, and the readout guard is an identity while retail’s readout invariant holds. The balance changes default to retail.

Shiny Seru
At each formation battle entry the engine rolls 2%: one capturable monster gets +35% HP / ATK / DEF / SPD, and capturing it marks the learned spell shiny (+35% damage). Off skips the roll and its rand() draw, which retail never takes, so every later battle-entry roll stays on retail’s position in the stream.
Run-away EXP
Any successful escape (Run, an item or a spell) banks 5% of the fled formation’s EXP into each member’s total, as the hook banks it: no level-up runs until the next won battle.
EXP rate
Each monster record’s base EXP is scaled before the victory sum with the patcher’s arithmetic (round half up, zero stays zero, otherwise 1..=65535); retail’s 3/4 scale and the per-member split run on the scaled sum.
Fortress battles fix
The encounter condition walk reads system flag 0x15 as clear in deroa and chitei2, falling past the Floating Castle’s copied "no battles" group (field oddities). The patch rewrites the table; the engine leaves it alone.
Boss casts respect jewels
Seven capture-class boss casts roll through the resist-respecting wrapper FUN_801DD4B0 instead of the bypass FUN_801DD6B4. That swaps the whole roll, not only the resist flag - the two wrappers read different attacker and defender terms (battle formulas).
Battle freeze guard
Before each frame of the HP-readout ramp, a party slot whose readout differs from live HP with nothing pending gets the difference re-seeded, so state 0x51’s settle check opens (exit gates).
Bonus equipment drops
Once per won battle, a 5% roll puts one equipment id straight into the bag, from the same pool the patcher embeds.
Save anywhere
The pause menu’s Save row works in every scene, not only where the scene header raises the save-allow bit. A port enhancement with no patcher counterpart.

Battle tuning

Each slider is one scale at the reader the patcher’s edit changes, with the patcher’s arithmetic. The patch scales the stored record; the engine scales at the reader, so a fight sees the same numbers but nothing on disc or in a save moves. Tetsu, the unwinnable sparring partner, is pinned against both enemy sliders, as the patcher pins him.

SliderWhat it scales
Enemy strengthHP, MP, ATK, UDF, LDF, INT and SPD of the monster record before the loader’s boost; AGL, EXP, gold and drops untouched

Verification

Each switch has a disc-free test that it changes behaviour when on and that its retail value is the unmodified path, across engine-core, engine-battle-vm, engine-session, engine-shell and web-play; the bonus-drop pool is pinned against the patcher’s by a disc-gated test. Tier 3 of the host-drift gate requires both hosts’ switch sites to pass the tweaks field, and the host frame trace digests the tweaks, so a switch thrown on one host only shows as a divergence.
