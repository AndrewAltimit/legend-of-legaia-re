Battle HUD and screen chrome

Everything the battle screen draws around the fight: the actor-name plaque, the party status readout, the command chips, banners, status and element badges, the item and magic windows. Retail does not draw this per frame from game state. It keeps a list of retained text actors, rebuilds that list from disc data at every state transition, and frames each actor with sprites looked up in two static tables. Knowing those two tables is enough to derive every seat, plate and palette on the screen.

Screen layout

How an element reaches the screen

  1. State edgethe command flow changes state, or the action SM seeds or finishes an action
  2. Sub-draw stepa script step lists (placement record, mode) pairs; a step flagged to reset first clears the handle list, so afterwards the live elements are exactly those pairs
  3. RaiseFUN_801D8DE8 reads the record and spawns a text actor at one seat, then arms a glide to the other
  4. Framethe per-frame draw dispatcher frames the actor with sprites from the widget-class record its frame-style byte names

The action SM opens its per-action elements in its seed arms and closes every one of them in the 0x51 band of the Done states.

The placement record

Each record is one element's pair of seats plus a shared content box. The two seats are the element's from and to: which one is the parked seat is per record, so some elements slide in from the right and others from the left or the top.

+0x00ids A / B2 × u8
+0x02seat A x, y2 × i16
+0x06width, height2 × i16
+0x0Aseat B x, y2 × i16
+0x0Eframe style A / B2 × u8
+0x10node kindu8
+0x11zero3 bytes
+0x14stringpointer

Mode bit 0 picks the spawn seat (A for 0, B for 1) and the glide runs to the other; bit 1 suppresses the glide.

  • The pen is (x, y - 2). Both seat arms subtract two from the seat's y before spawning the text actor.
  • +0x14 is the string being drawn. Name banners measure their string, write the width into +0x06 and centre both seats on it - which is how the move name stays centred on the screen whatever its length.
  • The plate is not stored anywhere. It is derived from the content box; one record derives every plate.

Three movers

Three small routines copy geometry and content between records - never the id, the box height or the frame - which is how one row can borrow another's content:

RoutineRole
FUN_801D5718lands an element: both seats become the source's seat B, so nothing is left to glide
FUN_801D57E8adopts a source's whole geometry into a row that keeps its identity
FUN_801D5778launches it: seat B becomes the source's seat B minus 0x140 - one display width, so it glides a screen to the left

The commit log uses all three: each committed member's name, command and target are landed into a row of three records, and earlier rows are launched off as the party commits.

The widget-class table

Every sprite the chrome draws comes out of one array. A placement record's frame-style bytes are indices into it: style 0x01 is the blue plate body, style 0x02 the carved-gold one. The join holds for all 103 placement records.

+0x00classu8
+0x01tile setu8
+0x02chain deltai8
+0x03CLUTu8
+0x04source u, v, w, h4 × u8
+0x08seat bias dx, dy2 × i16
  • A widget is a run of records. The chain delta steps to the next record of the same widget; zero ends the run. A roster panel is such a chain: plate, labels and separators.
  • The palette byte is a packed CLUT address, with bit 7 marking semi-transparency.
  • Two readers, one difference. FUN_8002C488 draws exactly one sprite at the caller's position and never applies the bias; FUN_8002C69C draws a sized widget, applies the bias, then follows the chain. The bias converts the glyph pen to the frame origin - the plate run's (-8, -4) takes the plaque's pen (16, 12) to a plate at (8, 8).

The table's end is structural: it runs exactly up to the frame tile-set pool the class arms read next.

Chrome facts worth knowing

  • One sheet, one three-slice, two palettes. The name plaque, the party bar and every command chip are the same three tiles (left cap, body, right cap) at two sheet rows: blue for the bar and chips, carved gold for the plaque. The gold row is the same art as the pause menu's title tab.
  • Numbers are cells, names are glyphs. Every number is a run of fixed 8×12 cells; only names use the proportional dialog font. Both halves of a current / maximum pair are right-aligned.
  • Status and element badges are widget records too: 48×16 word cells for the status element, 20×12 cells for the element badge, which is selected by markup in the name string rather than a placement record.
  • Four badge ids are not on the sheet at all - they resolve to the save-slot portraits.
  • The intro enemy-name banner uses immediate geometry, not a placement record.
